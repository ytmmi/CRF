# CRF 后续压缩算法探索路线

**记录日期**：2026-08-26  
**状态**：探索清单，尚未承诺进入码流或默认配置  
**适用范围**：首帧、残差、CPU 后端、GPU 后端

> **进度同步（2026-09-07）**：完成一轮**外部先进技术对标**（rANS/FSE、MANIAC/MA 树、
> JPEG-XL delta palette、上下文混合 CM/PAQ 等），结论见 §8。核心判断：
> **熵编码后端（rANS/FSE）对 CRF 无引入价值**（与 range coder 压缩率差 <0.3%，且
> LIFO 逆序与自适应 MA 树冲突）；**真正的高价值候选是 delta palette**——直击二次元
> 插画低色数场景，是 JPEG-XL 在该类别领先 PNG 近 50% 的主要来源（§8.4）。

本文把当前实现之上的候选算法集中记录，作为后续实验和评审入口。所有候选都必须
保持 V2 配置、闭环重建和无损码流语义不变；没有基准数据和回归测试的想法不得直接
合入主路径。

## 1. 当前基线与共同约束

- 首帧已有预测候选竞争、RCT/RGB 双路、IntraBC、RLE/Golomb/CABAC 和 frame_type=8
  变换路径。
- 残差已有 golden/previous 参考竞争、变化 Mask、整数位移补偿、场景切换 Anchor、
  序列码率控制，以及噪声感知和 RDOQ。
- CPU 具备 scalar 参考实现、AVX2 运行时分派和 Rayon 并行；GPU 目前是能力探测、
  阈值判断和安全回退框架，尚未把编码 kernel 作为默认依赖。
- 无损路径必须逐像素一致；有损路径必须以编码端重建帧作为后续参考。确定性模式下
  同一输入和 V2 resolved 配置产生相同字节流。

## 2. 首帧算法候选

| 候选 | 核心做法 | 预期收益 | 主要风险 | 首轮验证 |
|---|---|---|---|---|
| 分层帧内预测 | 4×4/8×8 块内对 DC、水平、垂直、Paeth、边缘方向做快速 SATD 预筛，再对 top-k 完整试编码 | 降低二次元立绘首帧体积 | 候选数增加导致延迟上升；边界上下文复杂 | 记录每候选命中率、首帧字节、p95 延迟 |
| 多尺度残差变换 | 平坦块走 transform-skip，纹理块在 4×4/8×8 DCT 与矩形变换间竞争；DC/AC 分离编码 | 集中高频能量，改善纹理压缩 | 变换系数语法和解码复杂度增加 | 固定候选上限，比较 bits/pixel 与 PSNR/SSIM |
| 调色板/索引块 | 低色数块使用局部 palette + 索引，palette 与预测路径按字节数竞争 | 赛璐璐平涂、服装和大面积同色区域显著收益 | 调色板头开销；细密网点块可能膨胀 | 按色数阈值分桶，验证单调不劣化 |

> **2026-09-07 外部对标升级**：调色板候选应扩展为 JPEG-XL 式 **delta palette**
> （详见 §8.4）：色数可 >256、delta 项编码"预测色与实际色的差"（渐变免 dithering）、
> 局部 palette。这是二次元插画场景压缩率的最大机会，建议优先级高于 §2 其余候选。
| 字典化重复纹理 | 扩展 IntraBC 的块签名索引，支持短距离 LZ/token 跨块复用 | 服装、网点、背景重复纹理收益 | 哈希冲突、索引表内存和最坏延迟 | 限定窗口和最大候选数，统计命中率/额外内存 |
| 首帧分区树 | 仅在大块预测代价明显较高时递归二分，深度由 effort 控制 | 细节密集区域减少预测误差 | 分区信令和递归搜索成本 | 与固定块基线比较首帧 R-D 曲线 |

首帧实验应优先从“分层帧内预测 + 已有 palette/IntraBC 竞争”开始；变换语法或新的
分区信令只有在码率收益稳定超过信令开销后才进入格式评审。

## 3. 残差与序列算法候选

| 候选 | 核心做法 | 预期收益 | 风险/约束 |
|---|---|---|---|
| 分块时间预测 | 对每个 tile 在 previous/golden/anchor 中选择参考，代价使用 SAD+少量 SATD | 降低表情、口型、服装等局部替换及组合差分的残差 | 必须携带参考选择并保证解码端可复现 |
| 多候选局部位移补偿 | 在整数位移之外尝试 2～4 个候选位移，采用稀疏网格搜索 | 发丝、饰品、衣褶等同一部件轻微错位时残差变小 | 搜索开销、边界处理和参考帧缓存增加；禁止为通用视频运动扩大搜索范围 |
| 稀疏系数语法 | 对 Mask 标记的静止 tile 使用零块 token/EOB；变化 tile 继续 CABAC/RLE 竞争 | 静止区域降低 run 与上下文开销 | Mask 误判会产生质量回退；需设置保守门控 |
| Anchor 关键帧优化 | Anchor 间隔按累计残差能量和大面积差分占比自适应，而非固定帧数 | 在短组及超过 50 帧的长差分组中抑制参考失配并控制复杂帧码率峰值 | 需要有界 look-ahead 或可回退的在线估计 |
| 分层码率控制 | 先分配序列预算，再按帧复杂度分配 tile 预算；保留最小质量下限 | 目标 bytes/bpp 更稳定 | 预算不足时必须确定性地降级候选和步长 |
| 残差熵模型选择 | 依据零值率、符号熵和 run 分布，在 RLE-Golomb、RLE-CABAC、Exp-Golomb 间快速选择 | 避免固定熵编码在异常分布下退化 | 统计成本和候选字节上限需要严格控制 |
| 误差扩散抑制 | 对高活动 tile 使用独立 anchor 或更小量化步长，对平坦 tile 使用更宽死区 | 改善主观质量并减少链式误差 | 需证明不会破坏闭环和码率单调性 |

残差路线的共同验收是：相同 V2 配置下，批量和 streaming 的参考选择、Mask、Anchor
位置及输出字节完全一致；任何只在编码端可见的启发式都必须有确定性版本。

## 4. CPU 优化算法

### 4.1 优先级高、风险低

1. 将 pixel diff、RCT、量化、绝对值/SAD、零值统计统一为连续内存 kernel，使用
   AVX2，并补充 AVX-512 与 ARM NEON 实现；scalar 作为逐位 oracle。
2. 对 4×4/8×8 块采用 cache tiling，复用预测、变换和重建缓冲，避免每条带创建
   `Vec`；以 scratch arena 管理临时内存。
3. 将候选预筛、条带统计和独立帧任务分层并行：小图保持单线程，大图才启用 Rayon，
   避免线程调度成本超过编码收益。
4. 位写入器采用批量 little-endian 写入和分支预测友好的 zero-run 快路径；CRC 与
   索引写入延后到整帧完成。

### 4.2 需要实验的方向

- PGO/Link-Time 优化和按 CPU 特性选择的多版本函数；禁止依赖 `target-cpu=native`
  生成不可移植产物。
- RDO 的并行候选评估：共享只读残差、独立输出缓冲，最终在单线程按字节数和失真
  做确定性归约。
- NUMA/大页内存只在超高分辨率或超过 50 帧的大型差分组中验证，不作为默认依赖。

## 5. GPU 优化算法

### 5.1 适合首批 GPU kernel 的工作

- 批量 pixel diff、RCT forward/inverse、420 重采样和 tile activity 统计；
- SAD/SATD 预筛、整数位移候选代价计算；
- 4×4/8×8 DCT、量化、死区和重建；
- 大批量候选的失真/字节近似代价计算。

这些工作具有规则访存和高算术强度，适合 CUDA/HIP/Vulkan compute。kernel 必须与
scalar 参考实现共享测试向量，并在整数边界、负残差和 i32 极值上逐位比对。

### 5.2 暂不迁移到 GPU 的工作

CABAC/RLE/Golomb 的强分支熵编码、帧头/索引/CRC、文件 I/O 和最终候选裁决先留在
CPU。推荐的混合流水线是：

```text
CPU 解析 V2/分配任务
  → GPU 批量 diff/RCT/预测代价/变换量化
  → CPU 确定性候选裁决与熵编码
  → CPU 重建、组帧、CRC 和 I/O
```

只有当 profiler 证明 CPU 熵编码成为主要瓶颈，且设备端能保持确定性，才评估把
significance map 或 run-level 编码迁移到 GPU。

### 5.3 传输与回退策略

- 以像素数、帧数、估算显存和 PCIe 往返时间建立阈值模型；低于阈值直接 CPU。
- 设备丢失、驱动/kernel 错误、显存不足或结果校验失败时立即回退 CPU，并在报告中
  记录原因。
- GPU 结果在 debug/CI 模式可抽样与 scalar 重算比对；确定性模式禁止浮点归约引入
  非确定顺序。

## 6. 实验矩阵与验收门槛

本项目的验收集只使用**二次元插画差分组**。自然照片、JPEG/WebP 有损噪声源、UI/图标、
通用视频平移和场景切换不作为算法收益样本，也不能用于扩大候选方案的胜率。超过 50 帧
的真实二次元差分组属于有效场景，必须通过流式路径纳入性能与稳定性验证。实验矩阵按
以下维度分层：

| 维度 | 必测分层 |
|---|---|
| 差分语义 | 眼睛/眉毛、口型/表情、发丝/发型、服装/饰品、手部/姿势、局部光影，以及其中两类以上的组合差分 |
| 变化面积 | 极小局部变化、小面积多区域变化、中等面积替换、大面积服装或姿势差分 |
| 绘制特征 | 赛璐璐平涂、细线稿与抗锯齿边缘、发丝和蕾丝等高频细节、网点纹理、二次元柔和渐变、高饱和色边 |
| 序列结构 | 同一底图的独立差分、可组合差分、相邻状态差分；帧数覆盖 2 帧、典型短组、50 帧边界及超过 50 帧的真实长差分组 |
| 尺寸 | 小尺寸立绘、常用立绘尺寸、高分辨率/超高分辨率立绘；保持项目真实宽高比 |
| 输入语义 | 项目支持的 PNG/BMP/TIFF 二次元原图；透明输入按项目既定 alpha/铺底规则形成独立回归层 |

固定回归应以仓库已有真实组为锚点，并扩充至少 30 个互不重复的二次元差分组。同一组的
相邻帧属于同一个统计样本，不能拆成多个样本放大胜率。每个分层都记录：

> 50 帧仅是当前批量 `encode_sequence` 接口的全帧驻留限制，不是 CRF 格式硬上限。
> 超过 50 帧使用 `StreamingEncoder`；当前码流帧数字段为 `u16`，实现上限为 65535。

- 总字节、首帧字节、残差平均/峰值字节和 bits/pixel；
- 编码/解码 p50、p95、首帧延迟、MPix/s；
- 全局与逐帧 PSNR/SSIM、最大误差，以及变化区域、未变化区域、线稿/色边区域的分区误差；
- CPU 利用率、线程数、峰值内存；GPU kernel、传输和设备利用率；
- 候选命中率、回退率、最坏耗时和确定性哈希。

进入实现的最低门槛：在二次元差分组加权结果上平均码率下降 ≥3%，或端到端编码时间
下降 ≥15%；同时各差分语义分层不得出现系统性退化，最差组需单独报告，不能用少数大图
掩盖表情/口型等小差分组的回退。有损方案还必须保证未变化区域不引入可见污染、线稿和
高饱和色边不出现稳定可辨的断裂或溢色；无损逐像素回归、batch/streaming 等价和跨后端
一致性必须全部通过。未达到门槛的方案保留在本清单，不改变默认 V2 行为。

## 7. 建议实施顺序

1. 建立统一 benchmark/telemetry，先测出现有首帧预测、残差 Mask 和 RDO 热点。
2. CPU 侧完成连续内存 + scratch + SIMD 泛化，锁定 scalar oracle。
3. 首帧先做分层预测与 palette/IntraBC 竞争；残差先做分块参考和自适应 Anchor。
4. 对已证明有收益的 diff/RCT/SAD/DCT kernel 实现 GPU，并接入现有 scheduler 的
   阈值和回退报告。
5. 最后评估 GPU 熵编码、分区树和新码流语法；任何格式变更单独提交规范、解码器和
   兼容性评审。

## 8. 外部先进技术对标（2026-09-07 调研轮）

对无损压缩领域当前主流技术路线做外部调研（来源：EUSIPCO 2023、FLIF/JPEG-XL 官方
文档与论文、heystacks 二次元插画基准、FSE 基准、pngprism、PAQ 系列论文），结论与
CRF 现状对齐后得到本节的候选增补/排除判定。所有结论均基于公开实测数据，**尚未在
CRF 上实施**。

### 8.1 熵编码后端：rANS / FSE —— 排除（压缩率无增益，实现成本高）

- **数据**：同一预测残差流上，算术编码 vs rANS 静态 1.614 vs 1.618 bytes/px、
  自适应 1.616 vs 1.619（EUSIPCO 2023）——**差异 <0.3%，无统计意义**。tANS 理论
  冗余度 O(σ/n) bits/symbol（arXiv:2201.02514），实际距香农极限 <0.1%。
- **吞吐**：rANS 解码 500–1500 MB/s、tANS 380–500 MB/s；但向量化 range coder /
  Huffman 解码 1223 / 1811 MiB/s 反超 SIMD rANS 的 556 MiB/s（Geldreich 2023）。
- **冲突点**：rANS 为 LIFO 逆序处理，与 CRF 自适应 MA 树（动态概率）天然冲突——
  需反转缓冲或静态概率，确定性码流下实现成本高、收益 <0.5%。
- **判定**：维持现有 range coder（CABAC 三变体竞争）。代表项目：JPEG-XL(rANS)、
  LZMA(binary range coder)、zstd(FSE)、CRAM 3.0(rANS, DNA)。

### 8.2 上下文建模：MANIAC 树生长 / JPEG-XL MA 树静态直方图 —— 值得借鉴两点

- **结构**：FLIF MANIAC = CABAC 变体 + 编码端在线生长的决策树（每叶 1 actual +
  每属性 2 virtual context，按编码成本决定分裂）；JPEG-XL MA 树为工程修正版——
  **静态直方图（解码端零更新）+ 叶节点直方图共享 + 树兼任预测器选择**。
- **CRF 现状**：已有 MA 树（深度≤3、8 叶子、4 属性 `|left|/|top|/|top_left|/
  |top_right|`、60 概率槽位）+ Gradient/Uniform 三变体竞争；预测器选择由候选竞争承担。
- **可借鉴**：①**直方图共享**（邻近叶复用概率分布，减少过拟合）②**静态化评估**
  （解码端去概率更新换吞吐——需先确认压缩率不退化，预计 +1~3% 收益窗口）。
- **判定**：低成本探索项；作为现有 MA 树上下文存储的替换而非新候选。

### 8.3 预测器：GAP / 加权预测 —— 低收益，可选第 11 候选

- **数据**：JPEG-XL 16 sub-predictor 自适应加权在 Kodak 仅 0.03–0.10 BPP 增益
  （WOP8 论文）；GAP 对"强边缘+平坦区"图片平均省 1800–3000 B/图但**全体平均为负**
  （Mamedov 2024）——预测器边际收益普遍 <1%。
- **判定**：CRF 已有 10 模式候选竞争，加 GAP 为第 11 候选成本低（候选竞争兜底单调
  不劣化），但预期整体收益 <1%，不作为优先项。

### 8.4 高价值：Delta palette（JPEG-XL 二次元插画领先 PNG 近 50% 的主要来源）

- **原理**（JPEG-XL delta palette，libjxl format_overview）：色数可 >256；palette
  颜色用 Average4 预测编码；**delta 项编码"预测色与实际色之差"**——渐变/平滑过渡
  用 delta=(0,0,0) 起始 + 小 delta 项，免 dithering；索引流用 Zero 预测器 + 局部
  256×256 palette。
- **量化收益**（heystacks 无损格式基准，Digital 2d Art 六类：Art/FanArt/Pixiv/
  Comics 等）：JPEG-XL e9 比优化 PNG **小 47–58%**，palette 为大头；pngprism 实测
  flat-color line art（7 色）JPEG-XL 304B vs PNG 533B（−43%）。CRF 差分场景
  （大面积不变 + 平坦色块 + 低色数立绘）与该工具精确匹配。
- **融合点**：作为 frame_type=4 的**扩展候选**（delta 项残差走现有 RLE/range coder），
  或新增独立帧类型；无损可逆、色数阈值探测可回退，单调不劣化由候选竞争保证。
- **判定**：**最高优先级探索项**——预期对低色数差分图额外省 10–30%，实现成本中等
  （调色板收集 + 索引流 + delta 项编码）。

### 8.5 上下文混合（CM/PAQ）—— 排除（违反硬约束），上限认知留档

- **上限参考**：EMMA/MATANE（竞赛级上下文建模）在 heystacks 同一次元插画基准上比
  JPEG-XL e9 **还小 11–13%**——业界工程路线（JPEG-XL/FLIF）距 CM 上限在插画域仍有
  ~10% 空间；paq8l 可对 JPEG 再压 20–30%。
- **排除理由**：CM 需数百模型 + 门控混合 + APM，解码端复现整个模型状态机；速度慢
  3–4 个数量级（kB/s 级）。违反 CRF 硬约束（纯 Rust、单文件 ≤1000 行、确定性码流、
  解码端不依赖编码端状态）。
- **折中**：MA 树 + 直方图共享（§8.2）即 CM 的工程化退化形式；未来可小幅扩展上下文
  属性（如 CALIC 式误差反馈），预期 ≤3%。

### 8.6 优先级总结（相对 §7 实施顺序的增补）

| 候选 | 预期收益 | 实现成本 | 融合方式 | 判定 |
|---|---|---|---|---|
| **Delta palette** | 低色数差分图 +10~30% | 中 | 扩展 frame_type=4 候选 | **优先探索** |
| MA 树直方图共享/静态化 | +1~3% | 低 | 替换上下文存储 | 低风险探索 |
| GAP 预测器 | <1%（整体） | 低 | 第 11 候选 | 可选 |
| rANS/FSE 熵后端 | <0.5% | 高（LIFO 冲突） | 替换 range coder | 排除 |
| 完整 CM/PAQ | ~10%（理论） | 极高 | 不适用 | 排除（硬约束） |

实施建议：delta palette 在 §7 第 3 步之前插入（先于分层预测泛化）；§7 第 5 步
"分区树/新码流语法"中的 palette 相关扩展与 delta palette 合并评估。

### 9.2 关键判定理由（与已证伪/已排除项的边界）

- **建议 1 与 §6.1#6 完全重合**：外部证据（MB-tree）进一步证实"帧级质量波动"与 CRF
  golden 统一质量语义（anchor_quality_percent=100 对标 AVIF 全帧）冲突；现有
  `RateControl` 已覆盖目标码率/最差帧护栏。
- **建议 3 与建议 10 是同一思路**（首帧误差补丁），合并评估；§16 的负结果不构成
  反证（其失败前提是误差注入差分帧，而非单独编码）。JPEG2000 的嵌入式设计是正确
  范式：精化层引用 G_hat（有损重建），否则两层冗余抵消收益。
- **建议 4 与已证伪证据链冲突**：DCT 零胜出 + λ 证伪 + 上下文证伪均指向"变换域在
  有损档缺乏竞争力的根因是内容本身（RCT+CfL 去相关后 planar/cabac 已近最优）"，
  非工具缺失。新增工具前应先有内容证据。
- **建议 8 的收益通道在 CRF 不存在**：SAO/DF 的码率收益来自"滤波→更粗量化→省码率"，
  无损逐像素语义下该等价通道消失；且 q85 可见瑕疵为噪点/色带（§26），与去块滤波的
  目标（块边界不连续）不匹配。
- **建议 6 与建议 7 是与现有框架融合度最高、竞争兜底最完整的候选**：LIC 作为参考
  帧加权（乘加模型）、prev2 作为第 3 参考候选，均不破坏候选竞争结构，DAT.1 可验证。
