### 2. 采纳实施项（v1.9）

#### A1. 斜向预测模式 TopRight(45°) + Diagonal(135°)　来源 §2.1 前半

- **理由**：二次元插画大量 ±45° 走向线条（头发丝、裙褶、网格）。现有 6 模式无斜向覆盖，
  MED 的平面外推仅在局部平面成立。新增两个纯因果斜向预测：
  - `TopRight = 7`：pred = 上行右移一位（右上邻居）；最右列回退 top，首行回退 left/0。
  - `Diagonal = 8`：pred = 沿主对角线上溯至边界的像素（top_left 链末端）；首行/首列分别回退 left/top。
- **机制红利**：候选进入既有 SAD 排序 → top-2 试编码 → 字节最小者胜出管线，**天然单调不劣化**；
  条带级/planar/CABAC 路径经同一 `predict_at` 自动受益；有损路径经闭环量化同样可用。
- **成本**：SAD 排序 6→8 模式（决策开销约 +15%，试编码仍取 top-2 不变）。
- **IntraBC（§2.1 后半）暂缓**：块搜索（hash 链/全搜索）工程量大；差分场景帧内重复纹理收益
  未证实，且会引入重建缓冲依赖的字典语义，与条带并行冲突。列入后续路线。

#### A2. MA 树因果属性扩展 +\|top_left\|　来源 §1.1

- **理由**：JPEG-XL MA 树实践表明，对角邻居属性能显著改善边缘走向的上下文区分度
  （水平边缘 vs 斜边缘在 \|left\|/\|top\| 二维下不可分，加入 \|top_left\| 后可分）。
- **实现**：属性数 2→3（`MA_ATTR_TOPLEFT=2`），训练采样与编解码两端 `attrs_at`
  同步补第三维；树序列化格式不变（attr 字段宽度本就是 u8，校验上界随 COUNT 自适应），
  **旧解码器不识别 attr=2 会拒绝载荷**——随 v1.9 版本升级，无需兼容层（新代码读写两端对称即可读旧文件：旧文件 attr∈{0,1} 合法）。
- **预期**：CABAC 候选码率再降 1~2%（v1.8 三模式竞争实测 −1.3% 的基础上）。

#### A3. DCT 感知量化矩阵　来源 §3.2

- **理由**：人眼对高频失真不敏感；当前 frame_type=6 对 16 个频率位置统一死区步长，
  高频系数"浪费"了精细度，低频又可能不够粗。
- **实现**（编码端本地化，**解码端零改动**）：
  - 4×4 权重表 `/64` 定点，按 `freq=r+c` 递增：DC=64（×1.0）→ 最高频=136（×2.125）；
    `Q_pos = clamp(base_q·w[pos]/64, 1, 255)`。
  - 量化输出仍是各位置 Q_pos 倍数的自描述残差——反量化隐含于残差值本身，
    与现有「解码端无感」哲学完全一致。
  - flat vs matrix 双版完整试编码竞争，取字节小者；矩阵启用标志记于载荷 k 字节 bit6
    （k≤6 占低 3 位，bit7 为 golden 语义所在帧头字段，载荷 k 字节的 bit7 空闲但为稳妥仅用 bit6）。
- **预期**：同档位体积再降 5~10%（有损 q75/q90），PSNR 允许 ≤0.5dB 内浮动（主观质量持平或更优）。
- **RDOQ/Trellis（§3.3）暂缓**：需率估计+动态规划，工程量大；4×4 小块下边际收益低于 A3。
- **多尺寸变换 8×8/16×16（§3.1）暂缓**：严格可逆 lifting 结构需重新推导，可逆性风险高；
  且 DCT 仅是有损多路竞争中的候选之一，大块收益会被 planar/RLE 路径分流。列入后续路线。

#### A4. 条带高度自适应（frame_type=2 增加 64 行档）　来源 §5.1

- **理由**：固定 32 行对大面积平坦插画偏细——条带头开销（每条带 mode+k+len 共 6 字节）
  与逐条带独立 k 的碎片化在平坦区是纯开销；纹理密集图则相反。
- **实现**：
  - 编码端 banded 候选跑 32/64 两档（height ≥ 128 才启用 64 档，避免小图无效试编码），
    与其他候选一并字节竞争；帧头 `coding_params` 记录实际条带高度（32/64 均 < 0x80，
    不触碰 golden 位）。
  - 解码端从帧头读取条带高度并校验 ∈ {32,64}；旧文件恒为 32，天然兼容。
  - 仅动 frame_type=2 的**预测条带高度**；noise 的量化条带（BAND_HEIGHT=32）语义不动。
- **预期**：无损自适应再降 1~3%。
- **16 行档不做**：条带头占比上升，收益为负的概率高。

## 四、v1.10 循环优化轮记录

按「复杂度 × 为后续铺路收益」降序循环实施；工程硬约束：单文件 ≤1000 行、模块分门别类。

### R1：多尺寸变换核 8×8 lifting DCT（原 H7，§3.1）

- **实现**：`transform/` 目录化（mod / dct4 / dct8 分类）。8 点核采用
  「镜像蝶形分离对称/反对称分量 → 对称路过精确 DCT-II₄ 骨架、反对称路经
  π/8 相位提升旋转走同核 → 偶奇交错输出」结构——每一步均为严格可逆原语，
  可逆性由构造保证；单频探针实测频率槽位单调映射（f→列f）。
- **集成**：frame_type=6 扩展为 **{4×4, 8×8} × {flat, 感知矩阵} 四版竞争**
  （载荷首字节 bit5=8×8 标记）；`dct_path` 拆分 `qm.rs` 子模块承载权重表
  （新增 QM8 64 位表）；解码端按 bit5 对称选择逆变换几何。
- **测试**：随机 1000 块逐位往返、极值边界、能量集中、探针响应。

### R2：RDOQ / Trellis 率失真优化量化（原 H8，§3.3）

- **实现**：独立 `encoder/rdoq.rs`。两状态上下文 Viterbi DP（游程延续 vs
  打断），每位置 ≤4 候选级 {near−1, near, near+1, 0}；率模型与 RLE+CABAC
  位流同构（escape+符号+Golomb 经验位长）；λ=8.5Q²（标定：偏移一级的失真
  ≥Q² 不应被 1bit 率收益收买）。仅作用于矩阵路径（flat 收益归零不跑 DP），
  以「胜者再竞争」策略挂接：四版竞争胜出配置追加 Trellis 版试编码，更小才采纳
  （载荷首字节 bit4=Trellis 标记）。
- **修复记录**：①λ 整数除法归零缺陷（率项统一放大 DEN 保精度）；
  ②Q=1 近无损保护档短路恒等；③残缺块几何与矩阵版对齐。
- **测试**：Q=1 恒等、稀疏场幅值不增 + 大系数保持、逐位置步长倍数不变式。

### R3 及后续轮次评估（v1.11 更新）

**R3 已实施：IntraBC 帧内块复制（原 H4，§2.1 后半）——用户指定，专攻首帧压缩。**

- **实现**：新 frame_type=7（`encoder/intrabc.rs` 522 行 / `decoder/intrabc.rs`）。
  - 双粒度搜索：块对齐签名桶（快速路径）+ 行段辅助索引（深度 32 行、
    步长 2 像素、同行增量插入——支持非块对齐的重复源定位，镜像/平移
    花纹均可命中）；
  - 三段式载荷：决策流 RLE + COPY 向量 exp-Golomb + PRED 预测残差 RLE，
    全部复用既有熵编码器；
  - **仅无损路径、仅首帧参与竞争**：首帧是自然原图、重复花纹主场；
    差分帧大面积零、RLE 已极致高效。
- **开发中发现并修复两处对称性缺陷**（均以回归测试锁定）：
  1. **DC 预测跨块引用**：DC 的 top_right=(x+1,y−1) 在 IntraBC 块级光栅序下
     可能落在右边邻块内——编码端可见完整原图而解码端尚未重建 → PRED 候选
     剔除 DC（其余模式仅依赖左侧/上方，因果安全）；
  2. **RLE 跨块截断**：RLE 零行程可跨块边界延续，按块切片消费时
     `decode_signed_array` 的 remaining 截断会丢弃行程尾部 → PRED 残差流
     改为一次性整体解码后按块切片取用。
- **验证**：100/100 测试 PASS；PNG1000 端到端 9/9 PASS（该组首帧精确重复块
  密度不足，IntraBC 未胜出——单调不劣化由竞争兜底；合成图案测试证实
  捕捉能力显著优于纯 RLE 基线）。真实收益取决于内容的重复花纹密度。

### R4：IntraBC 差分帧启用（v1.11 收尾，原已知限制解除）

- **根因定位**（端到端诊断 + 载荷级隔离复现）：
  1. **TopRight 预测跨块右引用**（与 DC 同病）：`TR=(x+1,y−1)` 在块最右列时
     落入**右邻块同一行带**——块级光栅序下尚未重建，编码端读原图、
     解码端读 0 缓冲 → PRED 候选剔除 TopRight（修复时曾漏剔，仅删 DC 不够）；
  2. **因果条件不完备**：旧条件 `syu < by` 允许「源块纵跨当前行带且不在
     左侧」的非法引用 → 改为完备形式 `syu+BS ≤ by ∥ (sxu+BS ≤ bx ∧ syu ≤ by)`，
     编解码两端同一判定。
- **验证**：诊断测试 `debug_itbc_diff_frame_e2e`（载荷级隔离复现 @213 失配 →
  修复后逐位一致）；101/101 全量回归 PASS；PNG1000/2000/c 三组端到端
  27/27 方案 PASS，体积与启用前持平（竞争兜底，单调不劣化）。

### R5：低优先级余项清尾（v1.11）

- **SAD 决策 rayon 并行化**：8 候选模式 `par_iter` 并行求值（纯函数无共享
  状态），多核下决策阶段耗时下降；体积零变化。
- **MA 树第四属性 \|top_right\|**（v1.11）：右上对角维度与 TopRight 斜向预测
  呼应；属性数 3→4，训练采样/编解码两端 attrs 同步（tr 仅在 stride≥2 时
  有效——stride=1 时 i+1-st=i 引用自身非因果）；序列化格式不变。
- **Trellis λ 多档竞争 —— 评估后跳过**：字节最小者胜出的竞争天然偏向
  小 λ（更激进归零 = 体积更小），会使 q90 档位 PSNR 失控下降而用户无感知，

### R14：S6 熵编码批量位写入实施记录（v1.13 续）

- **实现**：三个逐位编码器（`RleGolombEncoder` / `ExpGolombEncoder` /
  `GolombEncoder`）各增 `write_bits_msb(bits, n≤57)` 批量原语——大端位流
  拼接结合律保证与逐位 write_bit 产物完全一致：
  - **Golomb-Rice**：[q 个 '1'][终止 '0'][k 位余数] 合并单次写入；
    商 > tail_room(=56−k) 时按批直写全 '1'、尾批与终止符+余数拼合；
  - **exp-Golomb**：前导零天然是高位填充，总位宽 2m+1 下值本身即低位
    对齐——单次写入；m 超限分段保底（u32 值域内实际不可达）；
  - **RLE 零行程**：escape('1') 与 exp 合并单次写入（总位 2m+2，
    vp1 恒占低 m+1 位、中间零由空位天然补齐）。
- **开发中修复两处自引入缺陷**（对拍与回归捕获）：
  1. escape 合并位宽误写 2m+3（正确 2m+2）→ 零行程场景整体错位
     （20 测试失败定位）；
  2. 非零分支 escape 并入尾批宽度——大 q 分批场景下 escape 前缀落在
     1 串之后，位流虽自洽但偏离格式（3 测试失败定位）。修复为 escape
     显式单写 + 复用批量 encode_golomb。
- **等价性锚点**：新增 `test_batch_write_equivalence_to_legacy`——纯逐位
  参考实现（复刻改造前逻辑）× {k∈[0,16]} × {全零/长短行程/大幅值分批/
  高密度非零/极值边界} 五类数据集逐字节对拍 PASS。
- **验证**：114/114 测试 PASS；PNG1000 端到端体积与基线**逐字节一致**
  （10.35/8.76/4.11 MB）——码流零改动最终证明。
- **性能**：端到端总耗时 155.3s → 147.5~151.2s（≈−3%，机器负载敏感需
  多采样）；收益被管线中 I/O 落盘校验与 CABAC 主力路径（range coder
  不经本路径）稀释，Golomb 族试编码/banded/planar/palette 热点本身
  收益显著高于端到端表观值。

### 6.4 R8 排查记录：Fast-Fail 引入的体积回退假象与真缺陷

实施过程中经历一次完整的回归排查（10.35 → 10.52 MB），二分定位结论：

1. **真缺陷（已修）**：`RleGolombDecoder.decode_signed_array` 的 remaining
   截断会丢弃**跨块零行程的尾部**——Fast-Fail 按块消费残差流时触发
   （IntraBC 差分帧启用时同源问题）。修复：PRED/CABAC 残差流一次性
   整体解码后按块切片。
2. **真缺陷（已修）**：CABAC limited 函数初版「MA 变体超限即整体返回
   None」的错误推理——MA 含树头开销较大，其超限不代表 Uniform 变体
   会超限。修复：逐变体独立短路。
3. **假象（非缺陷）**：banded 排序键偏好在零场条带的多模式 SAD 平局时
   改变候选选择导致体积波动——该偏好收益本身趋零，实验后放弃。
4. **测量噪声**：编码耗时机器负载敏感，速度对比需干净环境多次采样。

最终状态：104/104 测试 PASS；PNG1000 端到端 9/9 PASS、体积 10.35/4.11/2.08 MB 与基线完全一致；2000 组复核 13.42/11.32/9.78 持平。

#### R11：首帧（Golden）专项建议评判（第四批，5 条——仅筛选记录，本轮不构建）

背景：超小序列（2 帧）实测首帧占 CRF 体积 53~97%——首帧压缩率即该场景
的整体压缩率，专项优化价值确凿。AVIF 静态图像工具箱的移植可行性逐条评判：

#### #1 超块递归分区（64×64 四叉树 → frame_type=8）

🟡 **中长期高价值项**。

- 技术面：本质是把 frame_type=2 的「水平条带级模式切换」推广为二维块级
  RDO。垂直维度已被 banded 部分覆盖；增量收益集中在「同行带内左右模式
  不同」与「行带内细粒度切换」场景。
- 收益修正：预估 8~12% 参照 AV1 全管线增益（预测+变换+熵联合），CRF 仅
  预测维度受益，实际预期 2~5%。
- 工程量为本批最大（新 frame_type、划分树序列化、逐块 RDO 循环），
  且无损模式下变换不参与、收益进一步收窄。
- 结论：保留为待实施高价值项，优先级排在 #3 之后；实施时建议先做
  「水平二分」（条带的列方向切分）验证增量再做完整四叉树。

#### #2 多参考行/列预测（Vertical_2 / Horizontal_2 / 线性外推）

🟡 低成本可做，**收益预期需从 5~8% 修正为 1~3%**。

- 因果安全 ✓、实现成本低（PredictionMode 扩枚举 + predict_at 分支 +
  测试，与 A1 斜向同款改动模式）✓、候选竞争保证单调不劣化 ✓。
- 收益修正理由：常数梯度下 top 与 top-2 给出相同预测（线性外推已被
  Med 平面外推覆盖）；真正受益的是 2 像素周期的网点/细条纹——存在但
  非插画主导纹理。
- 结论：作为候选扩充类低风险项保留，适合与其他模式扩展合并实施。

#### #3 RCT 自适应选择（首帧独立 YCoCg-R vs RGB 直通）

✅ **高优先采纳**（本批最佳）。

- 论点成立性核查：v1.11 否决针对的是**差分帧**（去相关后 Co/Cg 恒定使
  planar 受益）；首帧是自然原图，**高饱和纯色场景 RGB 域更稀疏的论点
  成立**——纯红背景 RGB=(255,0,0) 中 G/B 两通道恒零行程极长，而
  YCoCg-R 后三通道皆有值。
- 实现（文件级标志方案，格式变更最小）：文件头 flags 保留位（bit3）
  新增 `first_frame_no_rct`——编码端首帧双路竞争（RCT vs 直通各走完整
  管线取小）；解码端 decode_from_bytes/streaming 的 rct_inverse 出口按
  标志跳过 frame0。差分帧不受影响（其基准是首帧像素值而非存储格式）。
- 注意事项：streaming.rs 与批量路径需对称修改；无损/有损均受益；
  Fast-Fail 上限传递需按两条路径独立计算。
- 结论：高饱和插画（换装/纯色背景差分）真实场景常见，收益可信；
  工程量小（预计 <150 行含测试）。

#### #4 首帧专用 CABAC 上下文模型（model_id 位）

❌ **排除——前提错误**。

- 建议假设「MA 树基于所有帧（含差分）联合训练」，但实测代码
  （encoder/rle_cabac.rs L322）：`build_ma_tree(pixels, Some(st))` 在
  `encode_frame_rle_cabac_adaptive` 内对**每帧数据现场训练**，60 个概率
  槽位亦每帧从初始值重新自适应——CRF 天然满足「首帧用自己的分布训练
  自己的模型」，model_id 位无必要。
- 「离线预训练树结构先验」属 ML/数据积累范畴，项目规则禁止。

#### #5 DCT(Q=1) 首帧强化

🟡 部分（现状澄清 + 小增量）。

- 现状澄清：R7 已放开无损 DCT(Q=1) 候选——**首帧已在竞争中**；
  PNG1000 实测 frame0 由 type=5（CABAC 空间域）胜出，该组首帧 DCT

- 结论：矩形补齐随手可做；其余维持现状（竞争已覆盖）。

### R12：RCT 首帧自适应实施记录（v1.13，第四批 #3）

- **实现**：文件头 flags 新增 bit3 `first_frame_no_rct`——编码端对 golden
  首帧做「YCoCg-R 域 vs RGB 直通」双路完整管线竞争，字节最小者胜出
  （平局保守保持 RCT），直通胜出置位 bit3；解码端 decode_from_bytes /
  decode_from_file 出口按标志跳过 frame0 的 rct_inverse。
- **三路对称**：批量路径 G（首帧 bypass 候选取轻滤后 diff_rgb，保证有损
  golden_lossless=false 时两域质量语义一致）、路径 C（直通候选用原始
  frames[0]，pred_mode 继承源同步切换为胜者）、streaming（模块级
  encode_first_frame_bytes 复用编码入口）。流式与批量输出逐字节一致由
  新增测试锁定（bit3=0 与 bit3=1 两场景均比对）。
- **Fast-Fail 语义**：两路各自走完整自适应管线、各自内部 Fast-Fail——
  上限独立计算不跨路传递（跨路上限需扩散 encode_frame_adaptive 签名，
  收益仅省一次首帧编码的一半，不值得）。
- **开发中发现并修复一处既有缺陷**：streaming 首帧无条件 rct_forward，
  Gray 序列走流式 API 必报 InvalidCodingParams——改为按分量数分流，
  与批量路径 use_rct=false 行为对齐。
- **实测发现（重要）**：单一纯色极端场景（整图一色）下调色板候选在两域
  都收敛到「palette 表 + 单长行程」，体积分歧只剩表内几个 bit → 平局保守
  保持 RCT。真实收益场景是 **G=0 宽值域纹理**（换装插画的典型形态）：
  RGB 域 G 平面零行程极长、RCT 后三通道皆有值——单元测试以此锁定置位。
- **验证**：新增 5 测试（高饱和直通置位+往返+负向标志验证 / 自然内容
  RCT 保持 / 有损冒烟 / 路径 C / streaming 一致性）全 PASS；
  111/111 全量回归 PASS；PNG1000 端到端 10/10 方案 PASS、体积与基线
  逐字节持平（10.35/4.11/2.08 MB）——真实插画首帧 RCT 恒胜出，单调
  不劣化由竞争兜底，高饱和内容接入时自动兑现收益。

**工程合规**：最大文件 705 行 ≤1000 ✓；transform/{dct4,dct8,rect}、dct_path/{mod,qm}、intrabc×2 目录化分类 ✓。

## 六、v1.11 后续建议第二批评判（算法 9 条 + 纯速度 6 条）

评判基准：①禁止 ML 类（项目规则）；②速度类须保证码流逐字节一致；③算法类须不破坏「单调不劣化」与质量档位语义。

### 6.1 算法类评判

| # | 建议 | 判定 | 理由 |
|---|------|------|------|
| 1 | 自适应变换核形状（4×8/8×4 矩形）| 🟡 暂缓 | 技术可行（行 dct8 × 列 dct4 组合，载荷 k 字节 bit7 空闲可标形状）；但 v1.11 实测真实插画差分帧 DCT 候选出场率有限（planar/RLE 更优），在 DCT 已胜出的子场景内再提 5~10% 对整体码率影响 <2%。列入有损深化备选 |
| 2 | 内容感知 CABAC 上下文分组 | ❌ 排除 | 与 MA 树功能本质重叠——MA 树本身就是「帧头序列化的数据驱动决策树」，属性阈值分裂已隐式完成平坦/纹理分区；多树方案受 60 概率槽位上限约束，工程复杂收益存疑 |
| 3 | SSIM 导向 RDOQ | ⏸ 暂缓 | 编码端 only 码流零改动 ✓，但局部方差归一化 MSE 在 Trellis DP 内联计算成本高；主观收益无 SSIM 工具链可验证、不可证伪。待测试集扩展后评估 |
| 4 | 帧间模式概率继承 | ❌ 排除 | 安全版（仅重排候选顺序）SAD 仍全量计算 → 收益趋零；激进版（跳过低概率模式 SAD）在内容突变时错选最优模式 → 破坏单调不劣化。现有 preferred_mode 引导 + rayon 并行 SAD 已覆盖加速诉求 |
| 5 | RCT 自适应选择 | 🟡 暂缓 | 文件级双路竞争（整序列 RCT vs 直编取小）零格式改动可做，但 RCT 去相关后 Co/Cg 恒定使 planar 大幅受益——RCT 几乎恒优，反例罕见，预期收益极低；逐帧粒度需帧头新标志位（格式变更）不做 |
| 6 | 量化步长帧级自适应 | ❌ 排除 | 与 golden 架构的统一质量语义冲突（anchor_quality_percent=100 对标 AVIF 全帧 CRF）：帧级 Q 波动使部分帧质量不可控下降；且帧头无空闲位承载 Q 偏移 |
| 7 | 分层比特流随机访问（type=8）| ❌ 排除 | 伪需求：帧级随机访问已由帧索引 O(1) 解决；条带级跳过仅服务「单帧内部分渲染」这一查看器不存在的场景。新增 frame_type 收益场景为空 |
| 8 | ML 预测模式预筛选 | ❌ 排除 | 项目规则禁止 ML 类 |
| 9 | 测试集驱动调参平台 | ⏸ 数据依赖 | 方向正确但前置条件是测试集扩展（外部数据源），与 τ 联动/H9 合并为同一数据依赖项 |

### 6.2 纯速度类评判（约束：码流逐字节一致）

| # | 建议 | 判定 | 理由 |
|---|------|------|------|
| S1 | 试编码 Fast-Fail 短路 | ✅ **采纳实施** | 字节数单调递增 → 超阈值即必败成立，被淘汰候选的中途产物本就不会进入最终码流。RLE/CABAC 的 buffer 实时增长可随时检查。大图多候选场景节省败者约一半编码时间 |
| S2 | 残差全零块极速路径 | ❌ 排除 | 建议基于误解：RLE 行程机制本身已是零区的极速路径（连续零单符号编码），不存在更快的「内部快速路径」——若输出单字节标记则码流变更需解码端配合，与自称的「解码端无感」矛盾 |
| S3 | SIMD 预测/量化泛化 | 🟡 中长期 | Med/Paeth 为数据依赖分支向量化复杂；量化死区含整数除法（AVX2 无整除指令，需乘逆技巧）。易向量化部分（H/V/Avg）收益占比低。列为中长期选择性实施，本轮不动 |
| S4 | 内存池零分配 | ⏸ 暂缓 | Rust 分配器已很快且热路径多有 with_capacity；全局缓冲池在 rayon 并行下需 thread_local 改造侵入大。「10~15%」估计过于乐观。留作性能剖析后的定向优化 |
| S5 | 条带并行度自适应 | 🟡 部分 | 压缩条带高度部分已被字节竞争覆盖（小图条带少头部开销小自动落选）；rayon 执行层微开关收益微小。合并入日常优化不单列 |
| S6 | 熵编码批量位写入 | ✅ **采纳实施** | Golomb 商+终止+余数合并为单次 u64 写入（q+1+k ≤ 57 位安全）；exp-Golomb 的 m 计算现版已是 leading_zeros（建议方误判），但 (value+1) 可单次写入省去逐位循环。位对齐一致性由密集 roundtrip 测试锁定 |

### 6.3 本轮实施清单

1. **Fast-Fail 试编码短路**：`RleGolombEncoder` / `CabacEncoder` 增加 limit 参数，
   adaptive.rs 试编码调用点传入当前最佳字节数；
2. **BitWriter u64 批量写入**：Golomb-Rice 商/终止/余数合并写、exp-Golomb
   单次写（两者均限总位数 ≤57 防 u64 溢出）。

两项均为编码端内部改造，**码流逐字节一致**由既有 roundtrip 测试群锁定。

## 八、v1.15 有损目标预设口径修正与首帧路线（仅规划，本轮不构建）

### 8.1 用户目标修正

2026-08-25 进一步确认管线语义：项目只有相互并行的**有损管线**和**无损管线**；
Q95 不是独立管线，而是有损管线中的一个质量预设。目标高质量档的产品目标是正常
观看时肉眼几乎不可察觉，同时尽可能取得极大的压缩率；极大压缩率本身是 CRF 格式
的核心目标。

目标率失真点不预先固定为 Q95。应先完成 AVIF 对标与视觉标定，再按整套预设的质量
单调关系确定编号，可命名为 Q95、Q96、Q97 等。不能只给一个更低质量产物提高编号；
若采用 Q96/Q97，必须联合重标定 Q75/Q90/Q95 和相邻档位。

本轮外部主基线固定为 `E:\multimedia-compress\avif.py`。正常尺寸输入实际走
`av1_nvenc / p7 / vbr / cq=18 / yuv420p / bt709 / full range`，不是无损 AVIF。
因此上节 v1.14 的无损 AVIF/HEVC 首帧榜降级为无损管线旁证，不再用于定义目标有损
预设的质量和成功门槛。HVIF/HEIF 在没有明确同类脚本与产物前也不进入有损主榜。

### 8.2 现有产物重新判读

PNG1000 的现有 14 帧结果如下：

| 方案 | 完整大小 | 相对 AVIF | 全局 PSNR | 平均 SSIM | 最低单帧 PSNR |
|---|---:|---:|---:|---:|---:|
| AVIF CQ18 | 3,370,055 B | 基准 | 52.529 dB | 0.996707 | 52.307 dB |
| CRF 现有 Q95 | 9,180,717 B | +172.4% | 58.170 dB | 0.999143 | 56.217 dB |
| CRF 现有 Q90 | 4,309,282 B | +27.9% | 48.123 dB | 0.993907 | 45.308 dB |
| CRF 现有 Q75 | 2,176,958 B | -35.4% | 47.162 dB | 0.993336 | 43.956 dB |

文件字节数可作为现状基线；CRF 有损质量数值在下述 P0 修复前仅作诊断，因为现有测试
可能使用源 frame0 恢复 golden 帧，从而高估文件自包含解码质量。

现有 Q95 比目标多约 5.64 dB，但体积为 2.72 倍；现有 Q90 又比目标低约 4.41 dB。
当前有损管线在两个采样点之间缺少有效档位，不能继续用 `max_err <= 1` 定义目标档。

首帧问题更突出：q95 frame0 为 1,221,165 B，与无损 frame0 完全相同；对应首张
AVIF CQ18 为 248,121 B，q95 约为其 4.92 倍。现有各组 q95 首帧占完整文件
13.3%～97.4%，所以首帧仍是第一码率突破口。

### 8.3 P0 正确性前置

当前编码路径以原始 frame0 生成后续残差；首帧一旦有损，解码端实际只能拿到重建
首帧 `G_hat`，会出现参考失配。正确闭环应为：

```text
G_hat       = decode(encode(frame0))
residual[i] = frame[i] - G_hat
restored[i] = G_hat + decoded_residual[i]
```

编码端需先编码并重建 frame0，再并行处理其余帧。现有 `src-tauri/src/test/mod.rs`
恢复 golden 帧时重新加载源首帧 PNG，也会高估有损文件的真实质量；测试必须改为只用
CRF 解码出的 frame0。完成这两项前，旧 `golden_lossless=false` 质量数据不作为权威结论。

### 8.4 算法优先级修正

1. **目标档位与编号**：`Q_target` frame0 默认参加有损率失真优化；先找到目标
   率失真点，再用整套单调标定决定 Q95/Q96/Q97 等编号。无损 golden 仅作显式
   兼容选项，无损管线保持严格独立。
2. **真正启用色度降采样**：当前 `chroma_half_res = step > 1 && ...` 使 q95 的
   `step=1` 关闭 4:2:0；应把采样策略与整数步长解耦，并评估抽样/重建滤波。
3. **修复色度 Q=1 截断**：默认 130% 在整数运算下仍为 Q=1；改用定点步长、
   Q=1/Q=2 位置选择或量化矩阵/RDOQ 表达色度粗量化。
4. **首帧 intra 主路径**：固定 32/64 tile，组合局部预测、预测残差、4×4/8×8/
   矩形变换、transform skip、感知矩阵和 Trellis/RDOQ；用 `J=D+λR` 选择。
5. **系数专用熵语法**：逐块 EOB、方向扫描、significance map、DC 差分、AC
   magnitude/sign 分离、邻块非零/EOB 上下文，优先于继续深化整平面通用 RLE+CABAC。
6. **感知保护**：activity masking、平坦区防 banding、线稿/锐边/文字保护、饱和
   色边防 bleeding；客观指标作护栏，并加入分层主观 A/B 检查。
7. **序列后续方向**：基于重建参考竞争 golden/previous、稀疏变化 mask、轻量整数
   位移补偿、残差 tile 变换、场景切换新 anchor 和质量约束的帧级码率控制。

Q75/Q90/Q95/Q96/Q97 都属于同一有损管线，可共用工具和语法，但矩阵、λ、色度策略
需分别标定，并保持编号、质量与总体积的预设单调性。

### 8.5 阶段门槛

AVIF CQ18 指标作为可复现护栏，不替代目标预设“肉眼几乎不可察觉”的产品要求。候选先
通过正常观看、关键区域放大和最差帧检查，再在质量底线内选择最小字节。

- PNG1000 首轮质量搜索锚点：PSNR 52.529 dB（约 ±0.5 dB）、SSIM 0.996707
  （不低于目标 0.0005 以上）、最差帧不低于对应 AVIF 1.0 dB 以上；
- 阶段 A：匹配质量后完整 CRF ≤ AVIF +10%（3,707,061 B）；
- 阶段 B：匹配质量后完整 CRF ≤ AVIF（3,370,055 B）；
- 首帧阶段 A/B：匹配对应 AVIF 首帧质量后分别 ≤297,745 B / ≤248,121 B；
- 阶段 C：达到 AVIF 后继续降低字节，直到触及目标预设的视觉底线；不能把 AVIF 大小当作
  CRF 压缩探索的终点；
- 所有结果必须用 decoded `G_hat` 恢复完整序列，并报告 frame0、全局、逐帧和最差帧；
- 新码流语法在扩展验证集净收益低于 3% 时停止，不为单一 PNG1000 特例扩充格式。

完整原因、实验合同、分阶段路线、其他有损算法方向及停止条件见
[`first-frame-optimization-plan.md`](first-frame-optimization-plan.md)。本轮仍只做探索规划，
未修改或构建算法代码。

### 8.6 预设外的精细参数接口

预设只应是一组版本化默认配置，不能成为用户唯一入口。后续接口需支持：

- 从质量预设继承，再覆盖首帧质量、亮/色度量化、色度采样、感知保护、RDO λ、
  参考策略和码率约束；
