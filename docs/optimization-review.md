### 2. 采纳实施项（v1.9）

#### A1. 斜向预测模式 TopRight(45°) + Diagonal(135°)　来源 §2.1 前半

- **理由**：二次元插画大量 ±45° 走向线条（头发丝、裙褶、网格）。现有 6 模式无斜向覆盖，
  MED 的平面外推仅在局部平面成立。新增两个纯因果斜向预测：
  - `TopRight = 7`：pred = 上行右移一位（右上邻居）；最右列回退 top，首行回退 left/0。
  - `Diagonal = 8`：pred = 沿主对角线上溯至边界的像素（top_left 链末端）；首行/首列分别回退 left/top。
- **机制红利**：候选进入既有 SAD 排序 → top-2 试编码 → 字节最小者胜出管线，**天然单调不劣化**；
  条带级/planar/CABAC 路径经同一 `predict_at` 自动受益；有损路径经闭环量化同样可用。
- **成本**：SAD 排序 6→8 模式（决策开销约 +15%，试编码仍取 top-2 不变）。
- **IntraBC（§2.1 后半）暂缓**：块搜索（hash 链/全搜索）工程量大；差分场景帧内重复纹理收益
  未证实，且会引入重建缓冲依赖的字典语义，与条带并行冲突。列入后续路线。

#### A2. MA 树因果属性扩展 +\|top_left\|　来源 §1.1

- **理由**：JPEG-XL MA 树实践表明，对角邻居属性能显著改善边缘走向的上下文区分度
  （水平边缘 vs 斜边缘在 \|left\|/\|top\| 二维下不可分，加入 \|top_left\| 后可分）。
- **实现**：属性数 2→3（`MA_ATTR_TOPLEFT=2`），训练采样与编解码两端 `attrs_at`
  同步补第三维；树序列化格式不变（attr 字段宽度本就是 u8，校验上界随 COUNT 自适应），
  **旧解码器不识别 attr=2 会拒绝载荷**——随 v1.9 版本升级，无需兼容层（新代码读写两端对称即可读旧文件：旧文件 attr∈{0,1} 合法）。
- **预期**：CABAC 候选码率再降 1~2%（v1.8 三模式竞争实测 −1.3% 的基础上）。

#### A3. DCT 感知量化矩阵　来源 §3.2

- **理由**：人眼对高频失真不敏感；当前 frame_type=6 对 16 个频率位置统一死区步长，
  高频系数"浪费"了精细度，低频又可能不够粗。
- **实现**（编码端本地化，**解码端零改动**）：
  - 4×4 权重表 `/64` 定点，按 `freq=r+c` 递增：DC=64（×1.0）→ 最高频=136（×2.125）；
    `Q_pos = clamp(base_q·w[pos]/64, 1, 255)`。
  - 量化输出仍是各位置 Q_pos 倍数的自描述残差——反量化隐含于残差值本身，
    与现有「解码端无感」哲学完全一致。
  - flat vs matrix 双版完整试编码竞争，取字节小者；矩阵启用标志记于载荷 k 字节 bit6
    （k≤6 占低 3 位，bit7 为 golden 语义所在帧头字段，载荷 k 字节的 bit7 空闲但为稳妥仅用 bit6）。
- **预期**：同档位体积再降 5~10%（有损 q75/q90），PSNR 允许 ≤0.5dB 内浮动（主观质量持平或更优）。
- **RDOQ/Trellis（§3.3）暂缓**：需率估计+动态规划，工程量大；4×4 小块下边际收益低于 A3。
- **多尺寸变换 8×8/16×16（§3.1）暂缓**：严格可逆 lifting 结构需重新推导，可逆性风险高；
  且 DCT 仅是有损多路竞争中的候选之一，大块收益会被 planar/RLE 路径分流。列入后续路线。

#### A4. 条带高度自适应（frame_type=2 增加 64 行档）　来源 §5.1

- **理由**：固定 32 行对大面积平坦插画偏细——条带头开销（每条带 mode+k+len 共 6 字节）
  与逐条带独立 k 的碎片化在平坦区是纯开销；纹理密集图则相反。
- **实现**：
  - 编码端 banded 候选跑 32/64 两档（height ≥ 128 才启用 64 档，避免小图无效试编码），
    与其他候选一并字节竞争；帧头 `coding_params` 记录实际条带高度（32/64 均 < 0x80，
    不触碰 golden 位）。
  - 解码端从帧头读取条带高度并校验 ∈ {32,64}；旧文件恒为 32，天然兼容。
  - 仅动 frame_type=2 的**预测条带高度**；noise 的量化条带（BAND_HEIGHT=32）语义不动。
- **预期**：无损自适应再降 1~3%。
- **16 行档不做**：条带头占比上升，收益为负的概率高。

## 四、v1.10 循环优化轮记录

按「复杂度 × 为后续铺路收益」降序循环实施；工程硬约束：单文件 ≤1000 行、模块分门别类。

### R1：多尺寸变换核 8×8 lifting DCT（原 H7，§3.1）

- **实现**：`transform/` 目录化（mod / dct4 / dct8 分类）。8 点核采用
  「镜像蝶形分离对称/反对称分量 → 对称路过精确 DCT-II₄ 骨架、反对称路经
  π/8 相位提升旋转走同核 → 偶奇交错输出」结构——每一步均为严格可逆原语，
  可逆性由构造保证；单频探针实测频率槽位单调映射（f→列f）。
- **集成**：frame_type=6 扩展为 **{4×4, 8×8} × {flat, 感知矩阵} 四版竞争**
  （载荷首字节 bit5=8×8 标记）；`dct_path` 拆分 `qm.rs` 子模块承载权重表
  （新增 QM8 64 位表）；解码端按 bit5 对称选择逆变换几何。
- **测试**：随机 1000 块逐位往返、极值边界、能量集中、探针响应。

### R2：RDOQ / Trellis 率失真优化量化（原 H8，§3.3）

- **实现**：独立 `encoder/rdoq.rs`。两状态上下文 Viterbi DP（游程延续 vs
  打断），每位置 ≤4 候选级 {near−1, near, near+1, 0}；率模型与 RLE+CABAC
  位流同构（escape+符号+Golomb 经验位长）；λ=8.5Q²（标定：偏移一级的失真
  ≥Q² 不应被 1bit 率收益收买）。仅作用于矩阵路径（flat 收益归零不跑 DP），
  以「胜者再竞争」策略挂接：四版竞争胜出配置追加 Trellis 版试编码，更小才采纳
  （载荷首字节 bit4=Trellis 标记）。
- **修复记录**：①λ 整数除法归零缺陷（率项统一放大 DEN 保精度）；
  ②Q=1 近无损保护档短路恒等；③残缺块几何与矩阵版对齐。
- **测试**：Q=1 恒等、稀疏场幅值不增 + 大系数保持、逐位置步长倍数不变式。

### R3 及后续轮次评估（v1.11 更新）

**R3 已实施：IntraBC 帧内块复制（原 H4，§2.1 后半）——用户指定，专攻首帧压缩。**

- **实现**：新 frame_type=7（`encoder/intrabc.rs` 522 行 / `decoder/intrabc.rs`）。
  - 双粒度搜索：块对齐签名桶（快速路径）+ 行段辅助索引（深度 32 行、
    步长 2 像素、同行增量插入——支持非块对齐的重复源定位，镜像/平移
    花纹均可命中）；
  - 三段式载荷：决策流 RLE + COPY 向量 exp-Golomb + PRED 预测残差 RLE，
    全部复用既有熵编码器；
  - **仅无损路径、仅首帧参与竞争**：首帧是自然原图、重复花纹主场；
    差分帧大面积零、RLE 已极致高效。
- **开发中发现并修复两处对称性缺陷**（均以回归测试锁定）：
  1. **DC 预测跨块引用**：DC 的 top_right=(x+1,y−1) 在 IntraBC 块级光栅序下
     可能落在右边邻块内——编码端可见完整原图而解码端尚未重建 → PRED 候选
     剔除 DC（其余模式仅依赖左侧/上方，因果安全）；
  2. **RLE 跨块截断**：RLE 零行程可跨块边界延续，按块切片消费时
     `decode_signed_array` 的 remaining 截断会丢弃行程尾部 → PRED 残差流
     改为一次性整体解码后按块切片取用。
- **验证**：100/100 测试 PASS；PNG1000 端到端 9/9 PASS（该组首帧精确重复块
  密度不足，IntraBC 未胜出——单调不劣化由竞争兜底；合成图案测试证实
  捕捉能力显著优于纯 RLE 基线）。真实收益取决于内容的重复花纹密度。

### R4：IntraBC 差分帧启用（v1.11 收尾，原已知限制解除）

- **根因定位**（端到端诊断 + 载荷级隔离复现）：
  1. **TopRight 预测跨块右引用**（与 DC 同病）：`TR=(x+1,y−1)` 在块最右列时
     落入**右邻块同一行带**——块级光栅序下尚未重建，编码端读原图、
     解码端读 0 缓冲 → PRED 候选剔除 TopRight（修复时曾漏剔，仅删 DC 不够）；
  2. **因果条件不完备**：旧条件 `syu < by` 允许「源块纵跨当前行带且不在
     左侧」的非法引用 → 改为完备形式 `syu+BS ≤ by ∥ (sxu+BS ≤ bx ∧ syu ≤ by)`，
     编解码两端同一判定。
- **验证**：诊断测试 `debug_itbc_diff_frame_e2e`（载荷级隔离复现 @213 失配 →
  修复后逐位一致）；101/101 全量回归 PASS；PNG1000/2000/c 三组端到端
  27/27 方案 PASS，体积与启用前持平（竞争兜底，单调不劣化）。

### R5：低优先级余项清尾（v1.11）

- **SAD 决策 rayon 并行化**：8 候选模式 `par_iter` 并行求值（纯函数无共享
  状态），多核下决策阶段耗时下降；体积零变化。
- **MA 树第四属性 \|top_right\|**（v1.11）：右上对角维度与 TopRight 斜向预测
  呼应；属性数 3→4，训练采样/编解码两端 attrs 同步（tr 仅在 stride≥2 时
  有效——stride=1 时 i+1-st=i 引用自身非因果）；序列化格式不变。
- **Trellis λ 多档竞争 —— 评估后跳过**：字节最小者胜出的竞争天然偏向
  小 λ（更激进归零 = 体积更小），会使 q90 档位 PSNR 失控下降而用户无感知，
  与「质量档位语义」冲突。维持单一标定 λ=8.5Q²。

### R6：噪声感知 A/B 实验（数据驱动决策）

### R14：S6 熵编码批量位写入实施记录（v1.13 续）

- **实现**：三个逐位编码器（`RleGolombEncoder` / `ExpGolombEncoder` /
  `GolombEncoder`）各增 `write_bits_msb(bits, n≤57)` 批量原语——大端位流
  拼接结合律保证与逐位 write_bit 产物完全一致：
  - **Golomb-Rice**：[q 个 '1'][终止 '0'][k 位余数] 合并单次写入；
    商 > tail_room(=56−k) 时按批直写全 '1'、尾批与终止符+余数拼合；
  - **exp-Golomb**：前导零天然是高位填充，总位宽 2m+1 下值本身即低位
    对齐——单次写入；m 超限分段保底（u32 值域内实际不可达）；
  - **RLE 零行程**：escape('1') 与 exp 合并单次写入（总位 2m+2，
    vp1 恒占低 m+1 位、中间零由空位天然补齐）。
- **开发中修复两处自引入缺陷**（对拍与回归捕获）：
  1. escape 合并位宽误写 2m+3（正确 2m+2）→ 零行程场景整体错位
     （20 测试失败定位）；
  2. 非零分支 escape 并入尾批宽度——大 q 分批场景下 escape 前缀落在
     1 串之后，位流虽自洽但偏离格式（3 测试失败定位）。修复为 escape
     显式单写 + 复用批量 encode_golomb。
- **等价性锚点**：新增 `test_batch_write_equivalence_to_legacy`——纯逐位
  参考实现（复刻改造前逻辑）× {k∈[0,16]} × {全零/长短行程/大幅值分批/
  高密度非零/极值边界} 五类数据集逐字节对拍 PASS。
- **验证**：114/114 测试 PASS；PNG1000 端到端体积与基线**逐字节一致**
  （10.35/8.76/4.11 MB）——码流零改动最终证明。
- **性能**：端到端总耗时 155.3s → 147.5~151.2s（≈−3%，机器负载敏感需
  多采样）；收益被管线中 I/O 落盘校验与 CABAC 主力路径（range coder
  不经本路径）稀释，Golomb 族试编码/banded/planar/palette 热点本身
  收益显著高于端到端表观值。

### 6.4 R8 排查记录：Fast-Fail 引入的体积回退假象与真缺陷

实施过程中经历一次完整的回归排查（10.35 → 10.52 MB），二分定位结论：

1. **真缺陷（已修）**：`RleGolombDecoder.decode_signed_array` 的 remaining
   截断会丢弃**跨块零行程的尾部**——Fast-Fail 按块消费残差流时触发
   （IntraBC 差分帧启用时同源问题）。修复：PRED/CABAC 残差流一次性
   整体解码后按块切片。
2. **真缺陷（已修）**：CABAC limited 函数初版「MA 变体超限即整体返回
   None」的错误推理——MA 含树头开销较大，其超限不代表 Uniform 变体
   会超限。修复：逐变体独立短路。
3. **假象（非缺陷）**：banded 排序键偏好在零场条带的多模式 SAD 平局时
   改变候选选择导致体积波动——该偏好收益本身趋零，实验后放弃。
4. **测量噪声**：编码耗时机器负载敏感，速度对比需干净环境多次采样。

最终状态：104/104 测试 PASS；PNG1000 端到端 9/9 PASS、体积 10.35/4.11/2.08 MB 与基线完全一致；2000 组复核 13.42/11.32/9.78 持平。

#### R11：首帧（Golden）专项建议评判（第四批，5 条——仅筛选记录，本轮不构建）

背景：超小序列（2 帧）实测首帧占 CRF 体积 53~97%——首帧压缩率即该场景
的整体压缩率，专项优化价值确凿。AVIF 静态图像工具箱的移植可行性逐条评判：

#### #1 超块递归分区（64×64 四叉树 → frame_type=8）

🟡 **中长期高价值项**。

- 技术面：本质是把 frame_type=2 的「水平条带级模式切换」推广为二维块级
  RDO。垂直维度已被 banded 部分覆盖；增量收益集中在「同行带内左右模式
  不同」与「行带内细粒度切换」场景。
- 收益修正：预估 8~12% 参照 AV1 全管线增益（预测+变换+熵联合），CRF 仅
  预测维度受益，实际预期 2~5%。
- 工程量为本批最大（新 frame_type、划分树序列化、逐块 RDO 循环），
  且无损模式下变换不参与、收益进一步收窄。
- 结论：保留为待实施高价值项，优先级排在 #3 之后；实施时建议先做
  「水平二分」（条带的列方向切分）验证增量再做完整四叉树。

#### #2 多参考行/列预测（Vertical_2 / Horizontal_2 / 线性外推）

🟡 低成本可做，**收益预期需从 5~8% 修正为 1~3%**。

- 因果安全 ✓、实现成本低（PredictionMode 扩枚举 + predict_at 分支 +
  测试，与 A1 斜向同款改动模式）✓、候选竞争保证单调不劣化 ✓。
- 收益修正理由：常数梯度下 top 与 top-2 给出相同预测（线性外推已被
  Med 平面外推覆盖）；真正受益的是 2 像素周期的网点/细条纹——存在但
  非插画主导纹理。
- 结论：作为候选扩充类低风险项保留，适合与其他模式扩展合并实施。

#### #3 RCT 自适应选择（首帧独立 YCoCg-R vs RGB 直通）

✅ **高优先采纳**（本批最佳）。

- 论点成立性核查：v1.11 否决针对的是**差分帧**（去相关后 Co/Cg 恒定使
  planar 受益）；首帧是自然原图，**高饱和纯色场景 RGB 域更稀疏的论点
  成立**——纯红背景 RGB=(255,0,0) 中 G/B 两通道恒零行程极长，而
  YCoCg-R 后三通道皆有值。
- 实现（文件级标志方案，格式变更最小）：文件头 flags 保留位（bit3）
  新增 `first_frame_no_rct`——编码端首帧双路竞争（RCT vs 直通各走完整
  管线取小）；解码端 decode_from_bytes/streaming 的 rct_inverse 出口按
  标志跳过 frame0。差分帧不受影响（其基准是首帧像素值而非存储格式）。
- 注意事项：streaming.rs 与批量路径需对称修改；无损/有损均受益；
  Fast-Fail 上限传递需按两条路径独立计算。
- 结论：高饱和插画（换装/纯色背景差分）真实场景常见，收益可信；
  工程量小（预计 <150 行含测试）。

#### #4 首帧专用 CABAC 上下文模型（model_id 位）

❌ **排除——前提错误**。

- 建议假设「MA 树基于所有帧（含差分）联合训练」，但实测代码
  （encoder/rle_cabac.rs L322）：`build_ma_tree(pixels, Some(st))` 在
  `encode_frame_rle_cabac_adaptive` 内对**每帧数据现场训练**，60 个概率
  槽位亦每帧从初始值重新自适应——CRF 天然满足「首帧用自己的分布训练
  自己的模型」，model_id 位无必要。
- 「离线预训练树结构先验」属 ML/数据积累范畴，项目规则禁止。

#### #5 DCT(Q=1) 首帧强化

🟡 部分（现状澄清 + 小增量）。

- 现状澄清：R7 已放开无损 DCT(Q=1) 候选——**首帧已在竞争中**；
  PNG1000 实测 frame0 由 type=5（CABAC 空间域）胜出，该组首帧 DCT
  未占优。竞争顺序不影响字节比较结果，「提高优先级」无压缩率意义。

  两版——Q=1 下矩阵无效化但矩形形状仍有效），工程量极小（variants

- 结论：矩形补齐随手可做；其余维持现状（竞争已覆盖）。

- PNG1000 全组实测（RCT 域差分输入）：32 行档 banded 载荷
  11.363 MB → 11.311 MB（**−0.46%**），64 行档 −0.25%；二分胜出条带占比

  完整超块分区不做**——探针工具保留，供未来内容形态变化时复测。

**③ 多参考行/列预测 Vertical2/Horizontal2**（第四批 #2）

- 编解码两端经 predict_at 同一核心自动对称；非对齐尺寸往返由

### R12：RCT 首帧自适应实施记录（v1.13，第四批 #3）

- **实现**：文件头 flags 新增 bit3 `first_frame_no_rct`——编码端对 golden
  首帧做「YCoCg-R 域 vs RGB 直通」双路完整管线竞争，字节最小者胜出
  （平局保守保持 RCT），直通胜出置位 bit3；解码端 decode_from_bytes /
  decode_from_file 出口按标志跳过 frame0 的 rct_inverse。
- **三路对称**：批量路径 G（首帧 bypass 候选取轻滤后 diff_rgb，保证有损
  golden_lossless=false 时两域质量语义一致）、路径 C（直通候选用原始
  frames[0]，pred_mode 继承源同步切换为胜者）、streaming（模块级
  encode_first_frame_bytes 复用编码入口）。流式与批量输出逐字节一致由
  新增测试锁定（bit3=0 与 bit3=1 两场景均比对）。
- **Fast-Fail 语义**：两路各自走完整自适应管线、各自内部 Fast-Fail——
  上限独立计算不跨路传递（跨路上限需扩散 encode_frame_adaptive 签名，
  收益仅省一次首帧编码的一半，不值得）。
- **开发中发现并修复一处既有缺陷**：streaming 首帧无条件 rct_forward，
  Gray 序列走流式 API 必报 InvalidCodingParams——改为按分量数分流，
  与批量路径 use_rct=false 行为对齐。
- **实测发现（重要）**：单一纯色极端场景（整图一色）下调色板候选在两域
  都收敛到「palette 表 + 单长行程」，体积分歧只剩表内几个 bit → 平局保守
  保持 RCT。真实收益场景是 **G=0 宽值域纹理**（换装插画的典型形态）：
  RGB 域 G 平面零行程极长、RCT 后三通道皆有值——单元测试以此锁定置位。
- **验证**：新增 5 测试（高饱和直通置位+往返+负向标志验证 / 自然内容
  RCT 保持 / 有损冒烟 / 路径 C / streaming 一致性）全 PASS；
  111/111 全量回归 PASS；PNG1000 端到端 10/10 方案 PASS、体积与基线
  逐字节持平（10.35/4.11/2.08 MB）——真实插画首帧 RCT 恒胜出，单调
  不劣化由竞争兜底，高饱和内容接入时自动兑现收益。

**工程合规**：最大文件 705 行 ≤1000 ✓；transform/{dct4,dct8,rect}、dct_path/{mod,qm}、intrabc×2 目录化分类 ✓。

## 六、v1.11 后续建议第二批评判（算法 9 条 + 纯速度 6 条）

评判基准：①禁止 ML 类（项目规则）；②速度类须保证码流逐字节一致；③算法类须不破坏「单调不劣化」与质量档位语义。

### 6.1 算法类评判

| # | 建议 | 判定 | 理由 |
|---|------|------|------|
| 1 | 自适应变换核形状（4×8/8×4 矩形）| 🟡 暂缓 | 技术可行（行 dct8 × 列 dct4 组合，载荷 k 字节 bit7 空闲可标形状）；但 v1.11 实测真实插画差分帧 DCT 候选出场率有限（planar/RLE 更优），在 DCT 已胜出的子场景内再提 5~10% 对整体码率影响 <2%。列入有损深化备选 |
| 2 | 内容感知 CABAC 上下文分组 | ❌ 排除 | 与 MA 树功能本质重叠——MA 树本身就是「帧头序列化的数据驱动决策树」，属性阈值分裂已隐式完成平坦/纹理分区；多树方案受 60 概率槽位上限约束，工程复杂收益存疑 |
| 3 | SSIM 导向 RDOQ | ⏸ 暂缓 | 编码端 only 码流零改动 ✓，但局部方差归一化 MSE 在 Trellis DP 内联计算成本高；主观收益无 SSIM 工具链可验证、不可证伪。待测试集扩展后评估 |
| 4 | 帧间模式概率继承 | ❌ 排除 | 安全版（仅重排候选顺序）SAD 仍全量计算 → 收益趋零；激进版（跳过低概率模式 SAD）在内容突变时错选最优模式 → 破坏单调不劣化。现有 preferred_mode 引导 + rayon 并行 SAD 已覆盖加速诉求 |
| 5 | RCT 自适应选择 | 🟡 暂缓 | 文件级双路竞争（整序列 RCT vs 直编取小）零格式改动可做，但 RCT 去相关后 Co/Cg 恒定使 planar 大幅受益——RCT 几乎恒优，反例罕见，预期收益极低；逐帧粒度需帧头新标志位（格式变更）不做 |
| 6 | 量化步长帧级自适应 | ❌ 排除 | 与 golden 架构的统一质量语义冲突（anchor_quality_percent=100 对标 AVIF 全帧 CRF）：帧级 Q 波动使部分帧质量不可控下降；且帧头无空闲位承载 Q 偏移 |
| 7 | 分层比特流随机访问（type=8）| ❌ 排除 | 伪需求：帧级随机访问已由帧索引 O(1) 解决；条带级跳过仅服务「单帧内部分渲染」这一查看器不存在的场景。新增 frame_type 收益场景为空 |
| 8 | ML 预测模式预筛选 | ❌ 排除 | 项目规则禁止 ML 类 |
| 9 | 测试集驱动调参平台 | ⏸ 数据依赖 | 方向正确但前置条件是测试集扩展（外部数据源），与 τ 联动/H9 合并为同一数据依赖项 |

### 6.2 纯速度类评判（约束：码流逐字节一致）

| # | 建议 | 判定 | 理由 |
|---|------|------|------|
| S1 | 试编码 Fast-Fail 短路 | ✅ **采纳实施** | 字节数单调递增 → 超阈值即必败成立，被淘汰候选的中途产物本就不会进入最终码流。RLE/CABAC 的 buffer 实时增长可随时检查。大图多候选场景节省败者约一半编码时间 |
| S2 | 残差全零块极速路径 | ❌ 排除 | 建议基于误解：RLE 行程机制本身已是零区的极速路径（连续零单符号编码），不存在更快的「内部快速路径」——若输出单字节标记则码流变更需解码端配合，与自称的「解码端无感」矛盾 |
| S3 | SIMD 预测泛化 | 🟡 中长期 | Med/Paeth 为数据依赖分支向量化复杂；易向量化部分（H/V/Avg）收益占比低。量化死区的批量 SIMD 已在 P6.8 完成，预测部分继续列为中长期选择性实施。 |
| S4 | 内存池零分配 | ◐ 局部完成 | P6.9 已用帧作用域 `FrameScratch` 与 Rayon `map_init` 条带缓冲消除候选重复分配；全局/thread_local 池仍暂缓，避免锁与跨帧常驻内存。「10~15%」需基准验证。 |
| S5 | 条带并行度自适应 | 🟡 部分 | 压缩条带高度部分已被字节竞争覆盖（小图条带少头部开销小自动落选）；rayon 执行层微开关收益微小。合并入日常优化不单列 |
| S6 | 熵编码批量位写入 | ✅ **采纳实施** | Golomb 商+终止+余数合并为单次 u64 写入（q+1+k ≤ 57 位安全）；exp-Golomb 的 m 计算现版已是 leading_zeros（建议方误判），但 (value+1) 可单次写入省去逐位循环。位对齐一致性由密集 roundtrip 测试锁定 |

### 6.3 本轮实施清单

1. **Fast-Fail 试编码短路**：`RleGolombEncoder` / `CabacEncoder` 增加 limit 参数，
   adaptive.rs 试编码调用点传入当前最佳字节数；
2. **BitWriter u64 批量写入**：Golomb-Rice 商/终止/余数合并写、exp-Golomb
   单次写（两者均限总位数 ≤57 防 u64 溢出）。

两项均为编码端内部改造，**码流逐字节一致**由既有 roundtrip 测试群锁定。

## 八、v1.15 有损目标预设口径修正与首帧路线（仅规划，本轮不构建）

### 8.1 用户目标修正

2026-08-25 进一步确认管线语义：项目只有相互并行的**有损管线**和**无损管线**；
Q95 不是独立管线，而是有损管线中的一个质量预设。目标高质量档的产品目标是正常
观看时肉眼几乎不可察觉，同时尽可能取得极大的压缩率；极大压缩率本身是 CRF 格式
的核心目标。

目标率失真点不预先固定为 Q95。应先完成 AVIF 对标与视觉标定，再按整套预设的质量
单调关系确定编号，可命名为 Q95、Q96、Q97 等。不能只给一个更低质量产物提高编号；
若采用 Q96/Q97，必须联合重标定 Q75/Q90/Q95 和相邻档位。

本轮外部主基线固定为 `E:\multimedia-compress\avif.py`。正常尺寸输入实际走
`av1_nvenc / p7 / vbr / cq=18 / yuv420p / bt709 / full range`，不是无损 AVIF。
因此上节 v1.14 的无损 AVIF/HEVC 首帧榜降级为无损管线旁证，不再用于定义目标有损
预设的质量和成功门槛。HVIF/HEIF 在没有明确同类脚本与产物前也不进入有损主榜。

### 8.2 现有产物重新判读

PNG1000 的现有 14 帧结果如下：

| 方案 | 完整大小 | 相对 AVIF | 全局 PSNR | 平均 SSIM | 最低单帧 PSNR |
|---|---:|---:|---:|---:|---:|
| AVIF CQ18 | 3,370,055 B | 基准 | 52.529 dB | 0.996707 | 52.307 dB |
| CRF 现有 Q95 | 9,180,717 B | +172.4% | 58.170 dB | 0.999143 | 56.217 dB |
| CRF 现有 Q90 | 4,309,282 B | +27.9% | 48.123 dB | 0.993907 | 45.308 dB |
| CRF 现有 Q75 | 2,176,958 B | -35.4% | 47.162 dB | 0.993336 | 43.956 dB |

文件字节数可作为现状基线；CRF 有损质量数值在下述 P0 修复前仅作诊断，因为现有测试
可能使用源 frame0 恢复 golden 帧，从而高估文件自包含解码质量。

现有 Q95 比目标多约 5.64 dB，但体积为 2.72 倍；现有 Q90 又比目标低约 4.41 dB。
当前有损管线在两个采样点之间缺少有效档位，不能继续用 `max_err <= 1` 定义目标档。

首帧问题更突出：q95 frame0 为 1,221,165 B，与无损 frame0 完全相同；对应首张
AVIF CQ18 为 248,121 B，q95 约为其 4.92 倍。现有各组 q95 首帧占完整文件
13.3%～97.4%，所以首帧仍是第一码率突破口。

### 8.3 P0 正确性前置

当前编码路径以原始 frame0 生成后续残差；首帧一旦有损，解码端实际只能拿到重建
首帧 `G_hat`，会出现参考失配。正确闭环应为：

```text
G_hat       = decode(encode(frame0))
residual[i] = frame[i] - G_hat
restored[i] = G_hat + decoded_residual[i]
```

编码端需先编码并重建 frame0，再并行处理其余帧。现有 `src-tauri/src/test/mod.rs`
恢复 golden 帧时重新加载源首帧 PNG，也会高估有损文件的真实质量；测试必须改为只用
CRF 解码出的 frame0。完成这两项前，旧 `golden_lossless=false` 质量数据不作为权威结论。

### 8.4 算法优先级修正

1. **目标档位与编号**：`Q_target` frame0 默认参加有损率失真优化；先找到目标
   率失真点，再用整套单调标定决定 Q95/Q96/Q97 等编号。无损 golden 仅作显式
   兼容选项，无损管线保持严格独立。
2. **真正启用色度降采样**：当前 `chroma_half_res = step > 1 && ...` 使 q95 的
   `step=1` 关闭 4:2:0；应把采样策略与整数步长解耦，并评估抽样/重建滤波。
3. **修复色度 Q=1 截断**：默认 130% 在整数运算下仍为 Q=1；改用定点步长、
   Q=1/Q=2 位置选择或量化矩阵/RDOQ 表达色度粗量化。
4. **首帧 intra 主路径**：固定 32/64 tile，组合局部预测、预测残差、4×4/8×8/
   矩形变换、transform skip、感知矩阵和 Trellis/RDOQ；用 `J=D+λR` 选择。
5. **系数专用熵语法**：逐块 EOB、方向扫描、significance map、DC 差分、AC
   magnitude/sign 分离、邻块非零/EOB 上下文，优先于继续深化整平面通用 RLE+CABAC。
6. **感知保护**：activity masking、平坦区防 banding、线稿/锐边/文字保护、饱和
   色边防 bleeding；客观指标作护栏，并加入分层主观 A/B 检查。
7. **序列后续方向**：基于重建参考竞争 golden/previous、稀疏变化 mask、轻量整数
   位移补偿、残差 tile 变换、场景切换新 anchor 和质量约束的帧级码率控制。

Q75/Q90/Q95/Q96/Q97 都属于同一有损管线，可共用工具和语法，但矩阵、λ、色度策略
需分别标定，并保持编号、质量与总体积的预设单调性。

### 8.5 阶段门槛

AVIF CQ18 指标作为可复现护栏，不替代目标预设“肉眼几乎不可察觉”的产品要求。候选先
通过正常观看、关键区域放大和最差帧检查，再在质量底线内选择最小字节。

- PNG1000 首轮质量搜索锚点：PSNR 52.529 dB（约 ±0.5 dB）、SSIM 0.996707
  （不低于目标 0.0005 以上）、最差帧不低于对应 AVIF 1.0 dB 以上；
- 阶段 A：匹配质量后完整 CRF ≤ AVIF +10%（3,707,061 B）；
- 阶段 B：匹配质量后完整 CRF ≤ AVIF（3,370,055 B）；
- 首帧阶段 A/B：匹配对应 AVIF 首帧质量后分别 ≤297,745 B / ≤248,121 B；
- 阶段 C：达到 AVIF 后继续降低字节，直到触及目标预设的视觉底线；不能把 AVIF 大小当作
  CRF 压缩探索的终点；
- 所有结果必须用 decoded `G_hat` 恢复完整序列，并报告 frame0、全局、逐帧和最差帧；
- 新码流语法在扩展验证集净收益低于 3% 时停止，不为单一 PNG1000 特例扩充格式。

完整原因、实验合同、分阶段路线、其他有损算法方向及停止条件见
[`first-frame-optimization-plan.md`](first-frame-optimization-plan.md)。本轮仍只做探索规划，
未修改或构建算法代码。

### 8.6 预设外的精细参数接口

预设只应是一组版本化默认配置，不能成为用户唯一入口。后续接口需支持：

- 从质量预设继承，再覆盖首帧质量、亮/色度量化、色度采样、感知保护、RDO λ、
  参考策略和码率约束；

### 11.1 补充：帧类型胜出分布及其对 P1 第二轮的定向（2026-08-25）

verify 新增帧类型分布统计后，PNG1000 有损档位实测分布为：

| 方案 | 分布 |
|---|---|
| q95 / q90 / q75 | type3(planar)×13 + type5(CABAC)×1 |

**DCT(type6) 在全部有损档位零胜出**。由此修正 P1 第二轮路线：

- 量化矩阵标定（规划 §5-P1 第 4 项）的前提是变换域候选具备竞争力；

  a. 色度死区偏置独立化（chroma_deadzone_bias）；
  b. Co/Cg 平面的条带级自适应步长（复用 noise band 机制）；
  c. q95 档 deadzone 微调搜索（目标：质量带内进一步压字节）。

## 16. golden_lossless=false 标定扫描：关键负结果与边界确认（2026-08-25）

**目标**：评估放开首帧有损（golden_lossless=false）在扩展数据集上的
收益——规划 §3.2/§4.4 指出首帧占 q95 体积 28%（1.22 MB 近无损），
放开后首帧可对标 AVIF 248 KB。

**方法**：5 代表组 × {q95,q90,q75} × {ref(无损 golden), golden_lossy}，
CRF_GOLDEN_LOSSY=1 注入；首帧字节取自 index entry 0。

**决策表**（总体积 / 首帧字节 / 质量）：

| 组 | 档 | 总体积Δ | f0Δ | avgΔ | worstΔ |
|---|---|---|---|---|---|
| 1000 | q95 | **+60.4%** | −31.9% | **−15.63** | −8.34 |
| 1000 | q90 | **+93.4%** | −29.4% | −11.17 | −8.02 |
| 1000 | q75 | **+77.5%** | −58.5% | −11.14 | −7.60 |
| c | q95 | +21.5% | −51.4% | −11.60 | −4.88 |
| c | q90 | +23.2% | −56.5% | −5.17 | −4.49 |
| c | q75 | −14.0% | −73.8% | −8.40 | −7.35 |
| d | q95 | −9.3% | −52.3% | −3.60 | −3.15 |
| d | q75 | −9.8% | −69.9% | −3.37 | −2.56 |
| e | q95 | −1.4% | −32.5% | −17.01 | +0.20 |
| e | q75 | **−34.8%** | −67.9% | +0.16 | −0.38 |
| 纯差-1 | q95 | −1.4% | −40.0% | −1.27 | −1.13 |

**根因**：首帧量化误差注入差分残差能量——
`residual[i] = frame[i] − G_hat = (frame[i] − frame[0]) + (frame[0] − G_hat)`
首帧误差是全帧系统性偏移，注入每个差分帧 → 残差熵暴增 → 总体积爆炸
（P0 闭环虽阻止误差传导，但残差编码负担加重）。短序列/高首帧占比
组灾难性（1000 q90 +93.4%）；长序列/低占比组（e q75 −34.8%）才获益。

**裁决**：
1. **golden_lossless=false 不适合作为默认**——当前架构下是纯负优化
   （多数组体积+质量双输）；
2. 规划 §4.4 的"G_hat 残差"方向需要配合 P2 的"局部预测后变换"才能
   成立——预测能吸收系统性偏移、变换域对偏移残差更高效。这又一次
   指向变换域路线需要预测后变换才成立；
3. golden 无损保持默认 true——当前架构的正确选择；
4. 首帧专用 intra 路径（P2 完整版）是首帧压缩的唯一出路，但它需要
   专用熵编码器投入（§15 结论），构成路线依赖闭环。

**门禁**：扫描数据落盘 golden_scan.json；无代码改动（仅标定）。

**方法**：8 组 × {q90,q75} × {0(ref),±4,±8}。CRF_DEADZONE 环境变量注入。

**q90 决策表**（±4 饱和于 ±8，只列 ±4）：

| 组 | ref MB | dz=−4 Δ | dz=+4 Δ | avgΔ+4 |
|---|---:|---:|---:|---:|

## 25. frame_type=8 收益验证与编解码对称性缺陷修复（2026-08-26）

**目标**：落地 §24 未执行项 FT8.1（端到端往返）+ FT8.2（胜出率统计）——
frame_type=8 接入竞争后的真实 PNG1000 表现验证，以及 §24 标注的
"predict_block 两端独立维护耦合风险"排查。

**方法**：跑 PNG1000 adaptive 全量（无损 + q95/q90/q75）统计帧类型分布；
解析 test_adaptive.crf 帧索引定位解码失败；构造 RCT 域往返测试复现编解码
不对称。

**发现并修复两处缺陷**：

1. **banded coding_params bit7 golden 标志与条带高度冲突**
   （`decoder/mod.rs` L66）
   - 根因：路径 G 差分帧 `data[9] |= 0x80` 设 golden 标志于 coding_params
     字节，banded 帧（type=2）的 coding_params 同时承载条带高度（32/64），
     bit7 置位后变成 160(0xA0)/192(0xC0)，解码端
     `band_height = coding_params as usize` 未 mask bit7 → "非法条带高度 160"。
   - 既有缺陷：`is_golden_ref()` 注释称"bit7 恒空闲，安全"只看原始值，未
     考虑 golden 标志会被设上去；`golomb_k()` 已正确 mask（`& 0x7F`），
     palette 只读 bit0 不受影响——唯独 banded 分支漏 mask。
   - 暴露原因：此前 banded 在 PNG1000 从未胜出（type3×13 主导），
     frame_type=8 接入改变竞争格局后 banded 开始胜出（type2×7），触发此
     既有 bug。
   - 修复：`let band_height = (frame_header.coding_params & 0x7F) as usize;`
     （与 golomb_k 同语义）。

2. **CoeffCABAC encode_block 缺少终止 run → decode_block 越界读破坏后续块**
   （`encoder/coeff_cabac.rs`）
   - 根因：encode_block 只编码非零位置 (run, level, sign)，但当位置 0 是零
     （最小非零位置 > 0）时，decode_block 的 `while pos >= 0` 读完最后一个
     非零位置后 pos 仍 ≥ 0，继续循环越界读 bit，消耗 RangeCoder 状态，
     破坏后续块解码。
   - 触发条件：RCT 域差分值（含负值，Co/Cg 范围 -256~255）使某些块的
     zigzag 系数在位置 0 为零；RGB 域小值（0~255）巧合使位置 0 非零，故
     intra_transform_tests 的 q=1 测试通过未暴露。
   - 修复：encode_block 在所有非零位置编码完后，若 prev_pos（最小非零
     位置）> 0，额外编码一个终止 run=prev_pos 使解码端 pos 跳到 < 0 退出
     循环。
   - 验证：新增 `frame_type8_rct_domain_roundtrip` 测试（RCT 域负值 32×32
     块往返），修复前 max_err=231，修复后 max_err=0。

**附带清理**：`decoder/planar.rs` 三处 `eprintln!("DBG planar/sub/plane ...")`
调试残留删除。

## 30. CoeffCABAC 上下文深化证伪：方向扫描 / 邻块上下文合成内容探针（2026-09-06）

5~7 项）未做"。

**代码支撑**（本轮新增，码流零改动、纯编码端实验）：
- `performance/coeff_ctx_probe.rs`（`--probe-coeff-ctx`，无参数）：程序生成的 6 类
  合成内容（水平/垂直/斜向条纹、随机噪声、棋盘混合、渐变+斑块）× 双档量化
  （step=1/4），跑 frame_type=8 完整闭环（SAD 选 DC/H/V/MED → transform skip/DCT8
  → 量化 → 系数编码），对比 5 个变体的系数编码字节：
  - B（基线）：固定 zigzag + 单槽位 ctx_nonzero；
  - V1a/V1b（方向扫描）：H/V 模式改用 freq_x/freq_y 主序扫描（两种映射）；
  - V2（邻块上下文）：ctx_nonzero 4 槽位（按左/上块 EOB 索引）；
  - V3（组合）：方向扫描 + 邻块上下文。

**结果**（256×256 合成平面，字节 vs 基线，双档量化一致）：

| 内容 | 方向扫描 V1a/V1b | 邻块上下文 V2 | 组合 V3 |
|---|---|---|---|
| 水平/垂直条纹 | ±0.0% | **−1.3~−1.5%**（唯一微弱信号） | −1.3~−1.5% |
| 斜向条纹 | +0.0% | +0.0% | +0.0% |
| 随机噪声 / 棋盘 / 渐变斑块 | −0.1%~+0.0% | +0.0% | −0.1%~+0.0% |

**证伪结论**（两方向均 <3%，实际 ≈0%）：

1. **方向扫描证伪**：即使斜向条纹（残差大、DCT 系数大量非零，B=49355 字节），
   方向扫描也零收益——根因是块级 SAD 自适应预测已使残差能量集中在低频，zigzag
   （低频优先对角扫描）本就是 8×8 DCT 的最优扫描；方向性条纹更被预测完美消除
   （残差≈0）。freq_x/freq_y 主序扫描只是重排系数，run-level 总字节不变。

2. **邻块上下文证伪**：ctx_nonzero 只编码"块是否全零"一个 bit，量化后全零块
   占比高、该 bit 熵低（高度偏斜），单槽位自适应已逼近理论下限；4 槽位（左/上
   块 EOB 索引）的增量收益需要"邻块 EOB 强相关"，合成内容（棋盘交替）未提供
   足够相关性。唯一微弱信号（水平条纹 −1.3~−1.5%）远低于 3% 门槛。

**裁决**：
1. 方向扫描（P3.2）与邻块上下文（P3.5）在合成内容上均证伪，**不进入正式路径**；
2. 与项目既有证伪先例一致（R6 噪声感知自动启用、S0 ringing 非独立信号、S1 λ
   敏感性 ≈0.9%），CoeffCABAC 深化方向就此关闭——合成内容（理论上最易兑现收益的
   场景）都无 ≥3% 收益，真实二次元数据（帧率更低、分布更分散）更不可能；
3. 探针保留为回归锚点（`--probe-coeff-ctx`），供未来内容形态变化时复测；
4. CoeffCABAC 维持 4 上下文最小版（§24 已接入），不再深化。

（`test_streaming_previous_matches_batch` / `test_streaming_hybrid_matches_batch` /
`test_streaming_previous_quality_offset_matches_batch`，基线 3 failed）。

**根因**：streaming 的 previous 竞争骨架（`previous_rgb` 链式参考 + golden/previous
双候选 + 场景切换 + force_previous/字节竞争）此前已落地，但与批量路径
（`sequence.rs` L517-590）存在两处语义偏差：

1. **缺失 change_mask 稀疏变化掩码**（`sequence.rs` L537-544）。`change_mask` 默认
   `ToolMode::Auto`（不被 `resolve_auto` 改写为 On/Off），批量路径
   `!matches!(change_mask, Off)` 恒真 → previous 差分静止 tile 写零；
   streaming 缺失该步，previous 差分未稀疏化，编码产物偏大/不同。
2. **差分帧重建 rct_inverse 条件误用 `first_in_rct`**。streaming 差分帧重建

   不影响差分帧。首帧直通（bit3=1）内容下该偏差会使差分帧重建缺一次
   rct_inverse，破坏 previous 链式参考。

1. previous 差分 `sub_i32` 后、场景切换检测前插入 change_mask 处理
   （tile 阈值 `fq_base.step / 2`、`block_size.max(4)` 分块，与批量路径逐参对齐）；
2. previous 更新链的差分帧重建 rct_inverse 条件由
   `has_rct && !first_frame_no_rct` 改为 `has_rct`。

**验证**：
- streaming_tests 10/10 通过（含此前 3 failed → now pass）；
- 全量 `cargo test` 183 passed / 0 failed（基线 180 passed + 3 failed）；
- clippy 无新增告警（76 项为基线既有）；
- 无损路径零影响（previous 竞争仅在 `reference_mode != Golden` 时有损触发，

**附带**：批量路径的 previous 竞争本身（`sequence.rs` L517-590）为既有实现，

## 33. 平面空间预测 SIMD（components==1，P2 预测代价向量化，2026-09-07）

**目标**：performance-optimization-plan.md §P2「固定预测代价」——planar 子平面与
灰度帧（components==1）的空间预测是纯因果位移/算术，无递推依赖（无损域 pred 仅读
原始像素），可安全 AVX2 批量；Horizontal/Vertical/Average/DC 四模式入 SIMD，
Med/Paeth/斜向/多参考等分支密集模式保持标量 `predict_at`。

**实现**（码流零改动，`backend/cpu/simd_predict.rs` 新模块）：
- `predict_plane_avx2(pixels, out, width, mode, y_start, y_end) -> bool` 统一入口，
  按模式分派四个 AVX2 内核，返回 false 由调用方回退标量；
- 四内核覆盖 `apply_prediction_band_into`（紧凑缓冲）与 `apply_prediction_range_into`
  （整帧，y_start=0 时紧凑==整帧）两条预测路径；
- 向零除法（Average `/2`、DC `/4`）用「负值加偏置」修正
  `(x + (x<0 ? (1<<k)-1 : 0)) >> k`，与 Rust 整数除法截断舍入逐位一致
  （SIMD 仅算术右移 floor 语义）；
- 边界语义（每行首元素 / 绝对首行 / DC 四邻居边界）与 `predict_at` 逐位一致。

**验证**：
- `test_predict_plane_matches_scalar`：9 组尺寸（含 width=1/2/7、非对齐 33/37、
  条带起点 y_start=5、首行/尾行）× 4 模式，AVX2 与标量逐位一致；
- `test_trunc_div_bias_formula`：向零除法偏置公式逐值对拍；
- 全量 `cargo test` 185 passed / 0 failed（+2 项新测试）；
- 1000 组 bench 字节 11,090,743 逐字节不变（正确性保证）。

**性能结果（1000 组 release，三次 bench）**：

| 指标 | SIMD 前 | SIMD 后 | 变化 |
|---|---:|---:|---:|
| encode p50 | 7541ms | 7574~7597ms | ≈0（噪声内） |
| planar mean | 1595ms | 1395ms | −12.5% |
| planar.subplane_y | 474ms | 360ms | **−24.1%** |
| planar.subplane_co | 497ms | 429ms | −13.7% |
| planar.subplane_cg | 598ms | 578ms | −3.3% |
| banded mean | 418ms | 377ms | −9.8% |

**裁决——能力保留，不宣称正式接入**：

1. **热点收益真实但端到端被稀释**：subplane_y −24.1%（接近 §4.6 的 25% 门槛），
   planar −12.5%、banded −9.8%；但 planar 仅占 encode 约 21%（首帧 56% ×
   首帧占比 37%），planar −12.5% → 端到端仅约 −2.6%，落在测量噪声内（±2%），
   三次 bench encode p50 7541→7574~7597 无法稳定分辨。
2. **根因——预测为内存带宽瓶颈**：预测是逐像素「读 pixels + 写 residuals」，
   AVX2 减少指令数但无法突破内存带宽；SIMD 化 SAD 求和（同为带宽瓶颈）或
   合并 8 候选遍历（减少 pixels 重复读取）才有机会兑现端到端收益，属后续方向。
3. **保留理由**：字节逐位一致（正确性零风险）、热点有真实收益、建立
   `simd_predict` 模块为 components==3 预测 SIMD 与「合并遍历」铺路；
   与既有「能力保留待内容自动兑现」先例（无损 DCT 候选、V2/H2 预测）同列。
4. 若要兑现端到端收益，下一步应评估 components==3 交织布局的预测 SIMD
   （顶层 trial_encode/cabac/banded 的预测）与「一次遍历 8 候选」的内存合并，
   而非继续单点向量化。

## 34. 首帧 RCT 双路竞争探针：RGB 直通胜出率证伪「G 恒零」假设（2026-09-07）

**目标**：性能优化规划 §2.2 假设「首帧热点是候选预测」，而首帧 RCT 双路竞争
（v1.13）对首帧跑「YCoCg-R 域 vs RGB 直通」两路完整管线。若直通这路在自然
内容上从不胜出，可安全跳过（省约首帧一半耗时，≈18% 端到端）。文档 v1.13 声称
「自然相关内容 RCT 恒胜出，直通只在 G=0 高饱和内容胜出」——本探针验证该假设。

**代码支撑**（本轮新增，码流零改动）：`performance/probe_first_frame_bypass.rs`
（`--probe-first-frame-bypass <root>`，默认扫 test/png 全部组）——对每组首帧跑
RCT 域与 RGB 直通两路 `encode_frame_adaptive`，输出各自字节、直通胜出与否、
以及 G 通道零值占比。

**结果**（test/png 24 组首帧，release）：

| 结论 | 数值 |
|---|---|
| 直通（BYPASS）胜出组数 | **3 / 24（12.5%）** |
| 胜出组 | 2-1-2（−345KB）、2-12-4（−727KB）、2-3-2（−228KB） |
| 胜出组 G 零值占比 | **0.000~0.001（极低）** |
| 1000 组（RCT 胜出） | rct=1,221,165 vs bypass=1,275,047（+4.4%） |

**证伪结论**：

1. **「直通只在 G=0 高饱和内容胜出」假设不成立**：直通胜出的 3 组 G 零值占比
   均极低（0.000~0.001），与「G 通道恒零 → 零行程极长」的 v1.13 推断矛盾。
   直通胜出的真实原因更可能是 **RGB 通道间低相关性**（去相关收益不足、甚至
   反向引入残差），而非 G 通道恒零。
2. **「内容门控跳过直通」不可行**：G 零值占比无法预测直通胜出（胜出组与
   不胜出组的 G 零值占比同为 0.000~0.001），简单启发式会误伤 12.5% 组的字节
   收益（每组 −228~−727KB）；且 Fast-Fail 亦不可行——1000 组 bypass 仅比 rct
   大 4.4%，字节上限过松无法提前终止。
3. **首帧 RCT 双路竞争是必要的**：12.5% 组的直通收益可观（合计省 ≈1.3MB），
   不能为省时剪掉；RCT 双路竞争维持现状。
4. 探针保留为回归锚点（`--probe-first-frame-bypass`），供未来内容形态变化时
   复测；若未来要重新评估直通剪枝，需先找到**与 RGB 通道相关性**强耦合的
   低成本内容特征，而非 G 零值。

## 35. banded 条带高度（32 vs 64 行）胜出率探针：64 行档不可剪枝（2026-09-07）

**目标**：frame_type=2 在无损模式对每帧跑 32 行档 + 64 行档（height≥128）
竞争，各档都跑 8 候选精确 SAD + top-2 试编码。若 64 行档极少胜出，剪枝它可
省约一半 banded 时间（banded 为 encode 第二大热点）。本探针测量 64 行档

| 结论 | 数值 |
|---|---|
| 64 行档胜出 | **15 / 44（34.1%）**，累计省 9,639 字节 |

## 36. planar 子平面「外层并行 + 内层禁用并行」方向评估（2026-09-07，未实施）

**背景**：planar（frame_type=3）是单帧 encode 的最大串行块（约 50% wall clock，
3 子平面 Y/Co/Cg 串行，各子平面内部 rayon 并行）。P1c 曾尝试「去掉 preferred_sub
+ 3 子平面 par_iter（内层保持并行）」——无损字节一致但变慢 7%（嵌套过度订阅，
外层 3 线程瓜分 16 线程池，内层并行度下降抵消外层收益）。performance-optimization-plan.md
§P1c 遗留结论：planar 加速留待「外层并行 + 内层禁用并行」的线程预算重构。

**本轮评估（未实现代码）**：

1. **收益上限约 16.5%（乐观估算）**：planar 1395ms 三子平面若外层 3 路并行
   理想降至 465ms；但内层并行加速比不一（P1c 实测：dct 变体 ×3、cabac ×1.3、
   intra_transform ×1.15、SATD 8 候选、banded 条带并行），内层禁用后加权减速
   约 ×2~3，外层 ×3 加速与之对冲，净收益约 ×1.3~1.5——对应端到端 encode
   约 −8~16%，落在 10% 门槛两侧，需实测。
2. **字节风险（有损路径）**：外层并行必须去掉 `preferred_sub`（Y→Co→Cg 的
   历史引导，字节依赖）。P1c 已验证**无损**下去掉引导字节逐字节一致（planar
   无损从不胜出）；但**有损**下 planar 可能胜出，preferred_sub 会改变各子平面
   top-2 候选集，去掉后字节可能变化——需在有损 q90/q75 组重新锁定 batch/streaming
   逐字节一致，风险未消除。
3. **实现复杂度**：需 rayon `ThreadPoolBuilder(num_threads=1).install` 逐子平面
   隔离内层并行，且 Fast-Fail 字节预算检查从「逐子平面提前终止」改为「拼接后
   统一检查」——语义需重新论证（并行下无法按 Y→Co→Cg 顺序提前短路）。

**裁决——本轮停止循环，留待后续专项**：收益方向成立（约 −8~16% 端到端）但
存在有损字节风险与线程池隔离复杂度，且需先回答「内层禁用并行的真实加权减速比」
（当前仅凭 P1c 三点外推）。列入后续「性能优化规划 P1 收尾」待办，不在本轮
冒险改动有损语义。当前 encode 端到端瓶颈的其余候选（components==3 预测 SIMD、
「一次遍历合并 8 候选」）同属内存带宽/线程预算范畴，收益均需实测，一并留待
专项性能轮。

**✅ 已探针评估（2026-09-10，§51）——不实施**：`--probe-planar-parallel` 实测
内层减速比仅 1.5~2.2×（远低于本节外推 ×2~3），planar 阶段收益 +25%，但 planar 仅
占 encode p50 的 15.2% → 端到端 **+3.8%**（< 10% 门槛）；内存峰值无显著惩罚
（468.7 vs 452.6 MB）；生产路径去 `preferred_sub` 的有损字节**非透明**（q90
+0.42% 劣化 / q75 −0.87% 改善）。收益/风险比不划算，裁决改为**证伪、不实施**，
探针与 `CRF_PLANAR_NO_PREF` 钩子保留为回归锚点。详见 §51。

## 37. v1.14.1 遗留缺陷修复轮：type8 步长信令 + 路径 C 色度解耦 + 文件级往返（2026-09-07）

## 38. v1.15 破坏式更新：多参考帧（prev2）+ reference_type 帧头字段（2026-09-07）

**背景**：用户建议 7（多参考帧）落地。外部证据：Wiegand 1999 长时记忆多参考
帧间预测 +2dB≈34% 码率（Foreman）、通用 1→5 帧 5~15%，收益集中于周期运动/
遮挡重现——CRF 差分场景"相邻状态差分"（帧 N 与 N−2 更相似）真实存在。
用户授权**破坏式更新**（早期开发版本，无需兼容旧文件）。

### 格式变更（v1.15，不兼容 v1.14 及以下）

- `FRAME_HEADER_SIZE` 11 → 12：新增 `reference_type` 字段（data[11]），
  `VERSION_MINOR` 3 → 4。
- golden 参考语义从 `coding_params.bit7`（单 bit，仅区分 golden/链式）迁移到
  `reference_type` 三态：0=golden / 1=previous / 2=prev2 / 3=保留。
- 编码端：golden 不再写 coding_params.bit7（assemble_frame 默认 reference_type=0）；
  previous/prev2 候选写 data[11]。
- 解码端 `restore_temporal` / `decode_bytes_streaming`：三态还原，保留前前帧
  （prev2）历史。

### 多参考竞争（Hybrid）

- batch（`sequence.rs`）与 streaming（`streaming.rs`）对称实现：每帧对

## 39. palette 色数分布探针 + 像素级抽样预筛（2026-09-08）

**目标**：调色板候选（frame_type=4）在 telemetry 中累计耗时 30.7s/300 次
（mean 102ms），但文档 §30 仅记录「合成低色数可胜出」。用真实测试集
（test/png 全部组）统计 palette 可行性：
1. 分量级唯一值（当前 palette 判定尺度）与像素级(三元组)唯一值分布；
2. RCT 残差域差分帧的 palette 通过率——palette 真正参与竞争的语义位置。

**代码支撑**（本轮新增，码流零改动，探针保留为回归锚点）：
- `performance/probe_palette.rs`（`--probe-palette <root>`）——逐组输出首帧
  与差分帧的分量级/像素级唯一色数、抽样通过率。

**结果**（test/png 全部可用组）：
- **首帧分量级唯一值恒 = 256**（8bit 全值域），像素级 12 万~110 万；
- **差分帧（RCT 残差域）分量级唯一 320~506，44/44 全部 >256**；
- 差分帧 palette_plausible 抽样通过率 **0/44（0%）**。

**结论——palette 在真实插画数据上从不具备可行性**：
- 差分帧残差域分量级唯一必超 256，palette 载荷在 `map.len() >= 256` 即放弃；
- 首帧分量级恰卡在 256（等于上限、未超限），palette_plausible 无法提前
  否定，导致 encode_palette_payload 每帧完整执行全帧 HashMap + 索引流
  RLE 编码（5.6M 像素级），而像素级 12 万+ 色使其必然落败——这是
  palette span 30.7s 的成本来源（纯无效工作）。

**实施（`encoder/frame/candidate.rs` `palette_plausible` + 调用点）**：
- 新增像素级抽样唯一色数预筛：交织 RGB 下以 `step_by(7)` 同步统计
  三元组唯一数，超过 `PALETTE_SAMPLE_PIXEL_LIMIT=4096` 立即返回 false。
  真实插画首帧像素级 12 万+ 在数百次抽样内即触发，跳过后端全帧
  HashMap + 索引流编码；低色数内容（≤4096 色）完全不受影响、照常进入
  精确阶段，单调不劣化由竞争兜底。
- 阈值 4096 远高于合成测试的 4~256 色用例，仅剪「从两个尺度看均无可能
  胜出」的帧，产物逐字节由端到端锚点锁定。

**验证**：
- 1000 组 release bench：palette span **30.7s → 20.5s（−33%，mean 102→68ms）**；
- bytes **11090760 逐字节不变**（同工具链 HEAD 重编译基线）；
- 全量 release 190 passed / 3 failed（3 失败为既有 CUDA DLL 环境问题）。

## 42. D4 差分帧 dct 剪枝尝试与回退：探针采样完整性教训（2026-09-08）

**尝试**：承接 §41（差分帧探针 44 帧 dct 0 胜出、44.0s 耗时），对无损差分帧

1. dct 剪枝需「全部差分帧 + 与 HEAD 同工具链逐字节对拍全部组」双条件，

2. 探针新增 `CRF_PROBE_ALL_FRAMES=1` 全帧模式（按组使用时避免超时），

3. dct 的 44.0s 成本暂接受（竞争兜底保证单调不劣化，剪枝错误更贵）；
4. 教训沉淀：**任何基于胜出率探针的剪枝，采样必须覆盖组内全部差分帧，

## 43. D5 banded 合并 SAD 遍历尝试与回退：紧凑残差缓存优于合并遍历（2026-09-08）

**尝试**：banded 条带对 8 候选逐候选 `apply_prediction_band_into`（写残差缓冲）
后求和 SAD。认为可改为「单遍合并遍历：对每像素并行累加 8 模式 |残差|，仅
top-2 写残差缓冲」——省 6 次整条带写入与像素重复读（components>1 分支）。

**失败信号**：1000 组 encode p50 5375ms（dct 剪枝误触发同轮测量）→ 精确
对比下合并遍历使 **encode p50 7013ms（+30%）**，bytes 11090760 不变。

**根因**：合并遍历每个像素调用 8 次 `predict_at`（强分支的 Med/Paeth/斜向
模式），即使 pixels 只读一次，分支预测失败与内层循环膨胀的代价远超省下的
6 次线性残差写入；原 `apply_prediction_band_into` 的紧凑行缓冲布局在
components>1 下仍优于"少读多分支"。

**裁决——回退，维持原逻辑**：
1. banded 的 SAD 计算保持逐候选 apply+sum（紧凑缓冲线性写），这是实测
   更优的内存访问形态；
2. 该方向不再尝试；banded 速度优化若继续，应走 §33 的「SIMD 化 SAD 求和」
   或「一次遍历合并 8 候选」（减少 pixels 重复读取）中经过验证的形态，
   且必须先有 profile 证据；
3. 负结果沉淀：**合并遍历 ≠ 自动更优**——分支密集的 predict_at 是决定性
   成本，内存带宽仅在 SIMD 求和形态下才是主要瓶颈（§33 结论互证）。

## 45. banded preferred_mode 实现缺失缺陷记录（2026-09-08，不修复）

**缺陷**：`encoder/banded.rs` `encode_one_band_with_scratch` 的
`_preferred_mode` 参数**从未被使用**（下划线命名），但：
- 模块头注释（v1.11）声称「帧级 SAD 最优模式作为各条带的试编码顺序偏好——
  与 Fast-Fail 短路协同」；
- 排序注释声称「排序键附加偏好位：preferred 模式在同等 SAD 下优先」。
实际 `candidates.sort_by_key(|c| c.0)` 仅按 SAD 排序，偏好位不存在。

**影响评估（不修复理由）**：
1. **字节影响不确定**：若将 preferred 纳入试编码集（preferred + SAD top-2 共
   3 候选），banded 胜出字节可能变小（竞争增多、单调不劣化），端到端字节
   锚点 11090760 需重新确立；若仅作 SAD 相等 tie-break，则因 u64 精确 SAD
   相等罕见而实际零收益。
2. **速度代价明确**：banded 每条带多 1 次完整 RLE 试编码（约 +33% 试编码
   时间），而 banded 已是 encode 第二大耗时块（bench 累计 95.9s/300 次）。
3. **压缩率收益未验证**：帧级最优模式在该条带 SAD 排第 3+ 的情况占比未知，
   无探针数据支撑「漏选更优」的假设。

**裁决**：不修复，记录为已知缺陷。若未来做 banded 压缩率专项，先以探针
统计「preferred 在条带 SAD top-2 之外且字节更小」的频率，再决定是否
纳入试编码集（该方向收益 = 压缩率、代价 = 速度，需专项权衡）。

4. 数据驱动结论：N_CTX=60 独立槽位维持现状，不再投入该方向。

## 47. 首帧误差分离探针：JPEG2000 嵌入式分层数据驱动关闭（2026-09-08）

**目标**：§9 建议 3/10（采纳探索，高风险高回报）——首帧有损 + 误差层
单独编码（JPEG2000 嵌入式设计，精化层引用有损重建 G_hat 而非原图）。
核心验证式：`size(有损全序列 q90) + size(E 无损误差层)` vs `size(无损全序列)`。

**代码支撑**（本轮新增，码流零改动，探针保留）：`performance/probe_error_separation.rs`
（`--probe-error-separation <root>`）——每组编无损全序列 → 编有损 q90 全序列
→ 解码得 G_hat → E = frame0 − G_hat（RGB 域）→ 单帧无损编码 E → 对比两方案
总字节。每组取前 3 帧控制耗时/内存，大图组超 BATCH 限制自动跳过。

**结果**（大图组实测，其余组因耗时超时未跑完——负向信号已一致）：

| 组 | 无损全序列 | 有损+E | 差 |
|---|---:|---:|---:|
| 10-1-10 | 11,158,689 | 15,682,503（有损 6,476,289 + E 9,206,214） | **+40.5%** |
| 10-1-16 | 29,335,425 | 36,696,491（有损 20,608,030 + E 16,088,461） | **+25.1%** |

**裁决——关闭，维持首帧无损 golden 现状**：
1. **误差层 E 体积爆炸**：q90 首帧误差虽逐像素受控（≤⌊Q/2⌋），但误差
   分布广（插画渐变/抗锯齿处大量 ±1~2），RLE/熵编码无法有效压缩——
   E 单帧 9~16MB 远超有损首帧节省（相对无损首帧）；
2. **两层冗余确凿**：文档 §9.2 预估「独立两层 +5~10% 冗余」，实测
   +25~40%——误差层未引用 G_hat 而独立编码的空间是不存在的（JPEG2000
   的嵌入式前提是精化层逐步细化同一变换系数，CRF 的无损语义无此通道）；
3. 与 §16（golden_lossless=false 首帧误差注入差分帧暴增）机制不同但
   结论同向：首帧必须无损，误差不可分离——两层编码必然冗余；
4. 维持现状：golden 首帧强制无损（默认 true），未来不再投入该方向。

## 48. D6 banded SAD 求和 SIMD 尝试与回退：带宽瓶颈互证（2026-09-08）

**尝试**：banded 条带 SAD 求和改走 AVX2 批量 kernel（`backend/cpu/simd.rs`
新增 `sad_abs_sum`——补码绝对值与标量 `unsigned_abs` 逐位一致，含 i32::MIN

**失败信号**：同工具链 A/B 对比（1000 组 release）：

|---|---:|---:|

3. 速度优化继续应聚焦「减少像素重复读取」或「减少候选数量」，
   而非对已生成的残差流再做 SIMD 求和。

## 50. Delta palette（JPEG-XL 式）收益探针：场景错配否决（2026-09-10）

**目标**：闭环 compression-algorithm-exploration.md §8.4「最高优先级探索项」——
验证 JPEG-XL 式 delta palette（像素级调色板 + 条目 delta 编码 + 索引流
Zero predictor）对 CRF 差分场景能否带来 ≥3% 净收益，据此前置决定是否进入格式设计。

**探针实现**（`performance/probe_delta_palette.rs`，`--probe-delta-palette <root>`）：
1. **像素级(三元组)调色板收集**——现有 frame_type=4 按「分量级唯一值 ≤256」判定
   （尺度错配），本探针按像素级三元组去重，上限 65536 色；
2. **调色板条目 delta 编码**——按亮度排序后逐条目在 {zero, left, avg(left,left2)}
   三个 predictor 中选 |delta| 最小者，delta 走 exp-Golomb(zigzag)（复用现有编码器）；
3. **索引流多预测器竞争**——Zero / copy-above / 上差分（垂直）/ 左差分（水平）
   四者取字节小者，均走 RLE+Golomb 自适应 k（差分后不变区域归零 → RLE 长行程）；
4. **对比基准**——`encode_frame_adaptive` 当前最优候选（含帧头）；
5. **采样**——首帧 + 全部差分帧（`CRF_PROBE_TAKE` 可限制，默认全量）；
   差分帧路径 G 语义（RGB diff → RCT）。零外部数据集，仅扫 `test/png`。

**实测（release，test/png 全组，CRF_PROBE_TAKE=2 覆盖 22 组 52 帧）**：

| 指标 | 结果 |
|---|---|
| 色数 ≤65536 可行帧 | 10/52（首帧全部 >65536 色） |
| delta 估算 < 最优候选 | **0 帧** |
| 收益 ≥3% | **0 帧** |
| 整体字节（候选竞争兜底） | 413,988,719 → 413,988,719（+0.00%） |
| 最好情况（2-5-2 差分帧，7870 色） | 最优 6,499,368 B vs delta 8,753,640 B（**劣化 34.7%**） |

**根因（场景错配，非实现缺陷）**：
1. **首帧色数全部 >65536**——测试集立绘含抗锯齿/渐变，像素级三元组远超调色板
   可编码范围；文档设想的「低色数立绘」在当前数据集不存在；
2. **差分残差与调色板机制根本错配**——差分帧经 RCT 后大片 0/微小残差，最优
   候选（CABAC）已压到 0.03~0.5 bit/像素；delta palette 的索引流是「每像素一个
   索引 token」，且 ±1 微小残差导致相邻像素索引交替、RLE 失效（1000 组差分帧：
   3236 色、索引流 3.0 MB vs 最优 117 KB）；
3. **JPEG-XL 场景 ≠ CRF 场景**——JPEG-XL delta palette 针对「原始低色数图像」
   （平涂线稿）；CRF 的差分帧是「已高度稀疏的残差」，palette 的低色数索引优势
   被残差编码的稀疏零优势碾压。

**修正偏差后结论不变**：初版探针索引流 RLE 仅对值 0 生效（调色板排序后主残差
索引非 0，低估 delta palette）；加入上/左差分等 4 预测器竞争后重测，结论仍为
全面劣化——差距（34.7%~16000%+）非索引编码优化可弥补。

**裁决——否决，不进入格式设计**：
1. 不新增 frame_type=9、不占用任何码流格式位（遵守「未验证收益前不占格式位」）；
2. 探针 `--probe-delta-palette` 保留为回归锚点（同 §40/§46/§47 先例）；
3. 未来若引入「低色数平涂立绘」分层数据集，可重跑探针复评——但需先证伪
   「差分残差 vs palette 索引」的根本错配（如仅对变化区域 + 低色数内容）。

| 项 | 现状 | 预期收益 | 判定 |
|---|---|---|---|
| 一次遍历合并 8 候选 | `satd_for_mode_sampled` 对 8 模式各遍历一次（`par_iter`） | SATD 首帧仅 23.8 ms，全免也省 <1% | ❌ 收益极低 |
| components==3 预测 SIMD | 仅 components==1 已 SIMD（`simd_predict.rs`） | §33 已实测 components==1 预测 SIMD 端到端 ≈0（内存带宽瓶颈），三分量同理 | ❌ 不实施 |
| DCT/量化 SIMD | DCT 单变体内标量（`dct4/8x8_forward_into`）；量化已 SIMD（P6.8） | DCT 首帧 252ms 但 4 变体已并行，单变体 SIMD 受最慢变体限制 | ⚠️ 不实施（唯一有探索价值项） |

**根因**：
1. 三项均未直击首帧真实热点——首帧最大串行块是 planar（585ms，§51 已探针证伪
   并行化）与 CABAC/trial_encode；SATD 仅占 <1.5%，合并 8 候选收益窗口极小。
2. §33 已实测 components==1 预测 SIMD 端到端 ≈0（内存带宽瓶颈），components==3
   同理，SIMD 无法突破带宽瓶颈。
3. DCT 已由 P1c 变体级并行化（611→200ms），单变体 SIMD 的进一步加速受「最慢
   变体」串行约束，端到端收益低于 §4.6 的 10% 门槛。

**裁决——不实施**：
1. 三项均低于 performance-plan §4.6「端到端 ≥10% 或热点 ≥25%」门槛，且除
   「能力保留」外无端到端价值，不投入实现；
2. §P2 剩余待办关闭为「已评估、不实施」；
3. 未来若首帧瓶颈结构变化（如 CABAC/planar 占比下降使 DCT 成为主导），可复评
   DCT SIMD。

**§9 建议 9 探针**（`performance/probe_planar_band_mode.rs`，`--probe-planar-band-mode <dir>`）：

统计 planar 子平面帧内条带（32 行）最优预测模式与整帧最优模式的 SATD 差异。

实测（组 1000，1024×1820 首帧）：

| 子平面 | 整帧最优 | 条带级 SATD 收益 | 差异模式数 |

| Y | Med | **+4.5%** | 4 |
| Co | Med | **+6.8%** | 4 |
| Cg | Med | **+7.1%** | 4 |

1. planar 子平面**已有** banded（frame_type=2）条带级竞争（`encode_frame_adaptive`

   零胜出——说明条带级预测收益被 banded 的熵编码效率（RLE+Golomb）抵消；
2. SATD 收益 ≠ 字节收益，且需扣除条带头开销（§13 R13② 警示条带头翻倍侵蚀收益）。

**字节口径验证**（同一探针扩展）：对三子平面分别对比 A1 帧级最优模式 + CABAC、

|---|---:|---:|---:|
| Y | 476,266 B | 455,398 B | **−4.38%** |
| Co | 428,058 B | 435,309 B | **+1.69%** |
| Cg | 383,774 B | 389,547 B | **+1.50%** |
| 合计 | 1,288,098 B | 1,280,254 B | **−0.61%** |

（A2 现有最优 == A1：planar 子平面胜出即帧级 CABAC，与 probe_planar_sub 一致。）

**根因**：Y 子平面 SATD 收益（+4.5%）高度兑现为字节收益（−4.38%）；但 Co/Cg 的
SATD 收益（+6.8%/+7.1%）未兑现，反而字节劣化（+1.69%/+1.50%）——SATD 1/4 采样

**裁决——证伪，不实施**：整体净收益 **−0.61%**（即使仅对 Y 应用也仅 −1.62%），

`--probe-planar-band-mode` 保留为回归锚点。

## 55. GPU kernel 端到端加速比探针（P3/P4）：证伪不实施（2026-09-10）

**目标**：闭环性能优化规划 §P3（GPU 抽象与 Hybrid 探针）/§P4（NVIDIA CUDA）——
对现有 CUDA kernel（`diff_i32` / `rct_forward`）做 CPU vs GPU 端到端对拍，回答 P3
门槛「端到端 ≥1.5×」是否达成。

**环境**：NVIDIA GeForce RTX 4060 Laptop（8GB，驱动 610.88，compute 8.9）；
`crf_cuda.dll`（内嵌 PTX，Driver API 动态加载 nvcuda.dll）已构建。

**探针**（`performance/probe_gpu_kernel.rs`，`--probe-gpu-kernel`）：对
1024×1820×3 分量（5,591,040 i32）分别测 CPU（AVX2）与 GPU（含完整 device 分配 →
HtoD → launch → sync → DtoH → 释放）的 p50 耗时（5 轮中位），并校验逐位一致。

**实测**：

| kernel | CPU p50 | GPU p50 | 加速比 | 一致 |
|---|---:|---:|---:|---:|
| diff_i32 | 3.72 ms | 11.60 ms | **0.32×** | ✅ |
| rct_forward | 2.08 ms | 6.03 ms | **0.35×** | ✅ |

**根因**：
1. 现有 GPU 实现每次调用都完整 alloc→HtoD→launch→sync→DtoH→free，无缓冲复用/
   异步/双缓冲；diff 单次传输约 67MB（2 入 1 出 ×22MB），PCIe + 同步开销主导。
2. 数据规模（单帧 5.6M i32）不足以隐藏传输/启动开销——与 §33/§48「内存带宽瓶颈」
   结论一致；CPU AVX2 在 2~4ms 内完成，GPU 传输已 4ms+。
3. 即使按 §P4 规划加异步/双缓冲，diff/rct 为独立无重叠操作，传输下限（~4ms）
   仍使加速比 <1.5×。

**裁决——证伪，不实施**：
1. GPU 端到端 0.32~0.35×，远低于 P3 门槛（≥1.5×）；§P3/§P4 关闭为「已探针评估、
   不实施」；
2. `crf_cuda.dll` 与 GPU 分派路径（`backend/gpu/*`、`backend/ops.rs`）保留为
   「能力保留」（同 §33 先例），CPU 为默认且唯一实用后端；
3. §P5~§P7（AMD HIP/Vulkan、GPU-RDO、GPU 发布）以 P3/P4 成立为前提，一并关闭为
   「依赖已证伪项、不实施」；
4. 未来若出现「超大图/超长序列批量」且单次传输可摊销到足够计算量的场景，可复评。

**附带修复**：GPU 探针首次运行报 `crf_cuda_rct_forward export is missing`——根因是
`cargo build --release`（不带 `--workspace`）只构建 crf-viewer、不重建 `crf_cuda.dll`，
致 EXE 更新而 DLL 陈旧（缺 rct 导出）。修复：workspace 加 `default-members =
[".", "cuda-runtime"]`（普通 build 也重建 DLL）+ `runtime.rs` 加载候选改为 exe 同目录
绝对路径优先。修复后普通 build 同时编译 crf-cuda，探针稳定通过。

## 57. 调色板排序 + MTF 编码探针：证伪（2026-09-10）

**目标**：验证 §56 新候选「调色板排序 + MTF 编码」的净收益——排序后索引相邻 +
Move-To-Front 使渐变内容 rank 变小，是否改善 palette 压缩。

**探针**（`performance/probe_palette_mtf.rs`，`--probe-palette-mtf <root>`）：对分量级
色数 ≤256 的低色数帧（test/png-valid 30 图）对比三口径：
- A = 现有 palette（首现顺序 + copy-above + RLE+Golomb）；
- B = 排序调色板 + MTF 索引流 + RLE+Golomb；
- A2 = 现有最优（`encode_frame_adaptive` 全候选竞争）。

**实测**：

| 口径 | 合计字节 | 相对 |
|---|---:|---|
| A 现有 palette | 267,863,164 | — |
| B 排序+MTF | 234,153,319 | **−12.6% vs A** |
| A2 现有最优 | 18,509,416 | **B/A2 = +1165%** |

**结论**：
1. B 相对现有 palette（A）确有 **−12.6%** 改善（MTF 排序有效），但**远劣于现有最优**
   （A2）——palette 索引流每像素一个 token，而 cabac/planar 的残差编码对低色数内容
   已压到 1/10 以下。
2. 逐图仅 3 个极小像素画（9~28 色，3~9K 像素）B < A2（−9~−26%），绝对收益仅数 KB；
   其余全部 B/A2 +79%~+1165%。
3. 与 §50 delta palette 否决根因一致：palette 索引机制对 CRF 场景（残差稀疏/低色数）
   不敌残差熵编码。

**裁决——证伪，不实施**：MTF palette 端到端无价值（palette 不参与胜出），不新增码流

Fast-Fail** 两项。

## 58. JPEG-XL 式抖动调色板探针：证伪（2026-09-10）

**目标**：验证 §56 低优先候选「JPEG-XL 普通调色板 + 抖动」——有损抖动调色板能否在
可接受质量下显著省字节。

**探针**（`performance/probe_palette_dither.rs`，`--probe-palette-dither <root>`）：对
test/png-valid 低色数图（像素 ≤4M），均匀量化到 L³ 色（L∈{4,6,8} → 64/216/512 色）+
Floyd-Steinberg 抖动，测 PSNR + 像素级 palette 编码字节，与现有最优（无损 A2）对比。

**实测**（PSNR dB 范围）：

| 内容 | 64 色 | 216 色 | 512 色 |
|---|---:|---:|---:|
| illustration | 19.8~21.2 | 23.5~24.7 | 26.6 |
| lineart | 24.1~29.0 | 27.4~31.3 | 29.4~32.7 |
| manga | 18.4~19.4 | 22.8~24.5 | 24.9~28.3 |
| pixel_sprite | 19.4~33.6 | 24.2~36.9 | 24.7~38.6 |

**结论**：
1. 抖动调色板 PSNR **仅 18~39dB**，全部低于 40dB 门槛；即使 512 色最高也只 38.6dB。
   而项目有损 q90 达 **~45dB**——质量明显不足。
2. 字节上抖动调色板在 20~33dB 下确实小于无损 A2，但这是**低质量 vs 无损**的不可比
   对比；对比现有有损管线（q90 ~45dB）无优势。

| 10-1-10 | 9 | **−46.1%** | −17.1% |
| 30-1-36 | 9/36 | **−45.6%** | −21.1% |
| 2-12-4 | 3 | **−32.2%** | −23.5% |
| 1000 | 13 | **−27.1%** | −16.9% |
| 2-15-4 | 3 | **−12.0%** | −16.7% |

**结论**：
1. **首个显著正收益**：squeeze 在所有 6 组降低残差熵 −12%~−54.7%（前三次候选
   MST §63 / LICO §64 / WP §65 全部证伪）。
2. **但 CRF 现有编码仍优**：squeeze + RLE 仍比 CRF adaptive 差 16.7%~23.5%——
   CRF 的空间预测 + MA 树 CABAC 已捕获 squeeze 捕获的相关性。
3. **待验证**：squeeze 子带接 CRF 强编码器（而非 RLE+Golomb）能否产生净收益。
4. **背景**：libjxl 无损模式默认**不启用** squeeze（仅 `responsive`/渐进模式）；
   本探针为原创实验。

**裁决**：**正收益信号，待进一步验证**——squeeze 显著降低子带熵，但需与 CRF
强编码器结合测试净收益；探针 `--probe-squeeze` 保留。

## 67. Squeeze + CRF adaptive 组合探针：无净收益，证伪（2026-09-12）

**背景**：§66 探针显示 Squeeze 类 Haar 小波显著降低差分帧残差熵（RLE 口径
−12%~−54.7%），但 squeeze + RLE 仍比 CRF `encode_frame_adaptive` 差 17~24%。
本探针回答关键问题：**squeeze 子带接 CRF 强编码器能否产生净收益**。

**探针**：`--probe-squeeze-adaptive [root]`（`performance/probe_squeeze_adaptive.rs`，
零码流改动）。口径（每差分帧，RCT 残差）：
- A 交织 adaptive（当前生产路径）；B 分离分量 adaptive（隔离 squeeze 贡献）；
- C squeeze 子带 adaptive。

**实测（6 组，C vs A）**：

| 组 | 帧数 | B vs A | **C vs A** | C vs B |
|---|---:|---:|---:|---:|
| 2-12-4 | 3 | +6.0% | **+25.3%** | +18.2% |
| 1000 | 13 | +2.6% | **+17.6%** | +14.6% |
| 30-1-36 | 7/36 | +4.1% | **+17.4%** | +12.8% |
| 2000 | 7 | +1.9% | **+16.3%** | +14.1% |
| 10-1-10 | 7 | +3.8% | **+15.2%** | +11.0% |
| 2-15-4 | 3 | +2.3% | **+10.2%** | +7.7% |

**结论**：
1. **squeeze 无净收益**：C 在所有 6 组比 A 差 +10.2%~+25.3%。
2. **根因**：squeeze 子带已被小波去相关，内部空间相关性低 → CRF 的空间预测
   失效、CABAC 上下文效率下降；且子带分离增加每子带固定开销（帧头）。
3. **B vs A 佐证**：即使不 squeeze，分离分量也比交织差 +1.9%~+6.0%（交织布局
   本身有优势）。
4. **最终判定**：CRF 现有交织 adaptive 编码已优于所有 squeeze 方案。

**裁决**：**证伪，不实施**——§66 的"正收益信号"在接入 CRF 强编码器后消失，
squeeze 无净实施价值。与 MST（§63）/LICO（§64）/WP（§65）一致，**第四次印证
"CRF 预测+熵编码已高度优化，外部通用技术增量小"**。探针 `--probe-squeeze` /
`--probe-squeeze-adaptive` 保留为回归锚点。

## 68. 全局范式调研 + MA 树深度收益探针（P0-A）：部分收益，待实际编码验证（2026-09-12）

**背景（全局范式调研）**：跳出"CRF 架构内增量"，从全局视角调研无损图像压缩范式
（外部 librarian，2023-2026）。核心结论：
1. **预测+上下文建模就是动漫插画的最优顶层范式**——变换域（JPEG2000 7.30 bpp）、
   LZ（PNG 8.69 bpp）、视频无损（HEVC 10.33 bpp）均远差于 FLIF/JXL（3.39/3.47 bpp）。
2. **同范式内，上下文建模密度决定压缩率**：CM（EMMA）比 JPEG-XL 最强无损配置再小
   **11~13%**（Heystack：Art −11.6% / FanArt −13.3% / Manga −11.0%）。
3. **CRF 的 MA 树深度仅 3（8 叶子）、4 属性**，处于密度光谱最浅端——这修正了
   "CRF 已达架构局部最优"的判断：CRF 只是在其浅层模型内最优。
4. 语义级方向（变体补丁树 FSE 50% 无损、图层分解、形状码本）是另一条路。

**探针（P0-A）**：`--probe-ma-depth [root]`（`performance/probe_ma_depth.rs`，
零码流改动）。扫描 MA 树深度 3..8，测量 RCT 残差的**幅值桶条件熵**（bits/样本，
实际编码字节的下界代理）。

**实测（6 组，最优深度 vs d3）**：

| 组 | d3 条件熵 | 最优深度 | 收益 |
|---|---:|---:|---:|
| 30-1-36 | 0.275 | d6 | **−4.86%** |
| 10-1-10 | 0.140 | d5 | **−4.13%** |
| 1000 | 0.539 | d6 | −0.92% |
| 2-12-4 | 0.824 | d4 | −0.51% |
| 2-15-4 | 0.054 | d3 | 0.00% |
| 2000 | 0.051 | d3 | 0.00% |

**结论**：
1. **部分收益**：高熵组（残差信息量大）−4~−4.9%，低熵组（近全零）已饱和 0%；
   深度 5~6 后饱和。
2. **条件熵 ≠ 字节**：这是下界代理，实际 CABAC 字节收益需实测（通常小于熵降幅）。
3. **EMMA 的 11~13% 领先不主要来自树深度**：加深树仅 −0.5~−4.9%，差距来自
   多模型混合（CM）、长距离上下文、色彩变换、记录模型等**其他机制**。

**裁决**：**部分收益，待实际编码验证**——高熵组有 −4~−4.9% 条件熵收益，值得做
"MA 树深度可配 + 实际编码 A/B"验证；若实际字节达标则实施（需评估树头大小与
解码对称性）。探针 `--probe-ma-depth` 保留。

## 69. MA 树深度可配实现 + 真实编码字节 A/B（P0-A 闭环）：不达门槛，默认深度维持（2026-09-12）

**背景**：闭环 §68 裁决——条件熵探针显示高熵组加深 MA 树有 −4~−4.9% 收益，
需"MA 树深度可配 + 实际编码 A/B"验证该下界收益是否兑现为真实字节。

**实现**（默认字节透明，由 anchor 单测锁定）：
1. 运行时深度：`ma_max_depth()`（`OnceLock` 读 `CRF_MA_MAX_DEPTH`，clamp 1..=6，
   默认 3）；`build_ma_tree_with_depth` 承载训练，`build_ma_tree` 变薄包装
   （`core/entropy/context.rs`）。
2. `MaTree` 新增 `leaf_count` 缓存（`with_leaf_slots`/`single_leaf` 同步）；
   `deserialize` 上限改编译期 `MA_FORMAT_MAX_NODES=127`（解码端不读 env，对称红线）。
3. 扩展上下文布局（`leaf_count>8` 时启用）：`MA_EXT_ESCAPE=60`、`MA_EXT_VALQ=124`、
   `MA_EXT_SIGN=380`、`N_CTX=444`（推导式 + 编译期 assert 护栏）；`classify` 按
   `leaf_count<=8` 在编解码两端对称选择遗留/扩展布局。
4. `encode_ma_variant(.., max_depth)` 提取供探针复用；解码端删除本地重复
   `N_CTX=60` 改为 import `context::N_CTX`（消除 leaf>8 时越界 panic 隐患）。
5. 新探针 `--probe-ma-depth-ab`：每差分帧按生产口径（`sub_i32` → `rct_forward` →
   同 k）实测各深度 MA + Gradient/Uniform，主指标为整帧竞争
   `min(MA_dN,G,U)` vs `min(MA_d3,G,U)`（含树头字节）。

**实测（整帧竞争真实字节，负 = 更小）**：

| 组 | 帧数 | §68 条件熵（最优深度） | MA 单独 d6 | **整帧竞争 dN vs d3** |
|---|---:|---:|---:|---:|
| 30-1-36 | 5/36 采样 | −4.86% (d6) | −1.22% | **−1.22%** |
| 10-1-10 | 9 | −4.13% (d5) | −0.23% | **−0.30%** |
| 1000 | 13 | −0.92% (d6) | −0.31% | **−0.31%** |
| 2000 | 7 | 0.00% (d3) | −0.56% | **−0.59%** |
| 2-12-4 | 3 | −0.51% (d4) | +0.35% | **−0.14%** |
| 2-15-4 | 3 | 0.00% (d3) | 0.00% | **0.00%** |

**结论**：
1. **条件熵收益大幅衰减，6 组全部 <3% 门槛**：最高熵组 30-1-36 −4.86% →
   −1.22%（约 4× 衰减），10-1-10 −4.13% → −0.30%（约 14× 衰减）。
2. **根因**：① 条件熵是理想静态下界，CABAC 自适应概率已捕获大部分上下文相关性；
   ② 深度 6 满树头 ≤380B（vs 深度 3 ≤75B）抵消部分收益；③ MA 变体常非整帧胜出
   （Gradient/Uniform 竞争兜底），加深仅在 MA 胜出帧生效；④ 训练受 `MA_MIN_GAIN=0.04`
   / 5 桶 / 4 候选阈值约束，实际叶数在 d5 即饱和（d5=d6）。
3. 与 §63~§67 一致印证：CRF 预测 + 熵编码已高度优化，加深单棵上下文树增量有限；
   EMMA 的 11~13% 领先不来自单棵树的深度，而来自多模型混合/长距离上下文等机制。

**裁决——不达门槛，默认深度维持，能力保留**：
1. 默认 `depth=3` 维持（默认字节透明由 `test_default_bytes_anchor` 锁定）；
2. 深度可配能力（`CRF_MA_MAX_DEPTH`）+ 扩展布局 + 探针 `--probe-ma-depth-ab`
   保留为回归锚点（同 §40/§63~§67 先例）——未来若引入高熵内容分层，或放宽
   `MA_MIN_GAIN`/增密候选阈值（独立第二杠杆），可直接复测；
3. P0-A「加深 MA 树」方向关闭为「已探针评估、不达门槛」。

## 70. MA 树训练参数第二杠杆探针（P0-A 续）：显著正收益，建议实施（2026-09-12）

**背景**：§69 证明加深 MA 树（深度）只换来 −0.3~−1.2% 真实字节，瓶颈在**训练参数**——
`MA_MIN_GAIN=0.04` 与仅 4 个候选阈值 `[2,6,14,30]`（所有 >30 的残差被 lump 进同一侧，
大幅值尾区完全无区分度）。本轮把训练参数可配（`MaTrainParams` + env 钩子，默认逐位透明），
并新增 `--probe-ma-train-ab` 扫描 `gain × 阈值集 × 深度` 网格的真实字节。

**实现**（默认字节透明，由 anchor 单测锁定）：
1. `MaTrainParams { min_gain, thresholds, min_samples }`（`Default` 与历史常量逐位一致）+
   `ma_train_params()` OnceLock（env `CRF_MA_MIN_GAIN` / `CRF_MA_THRESHOLDS`）；
2. `build_ma_tree_with_params`（生产与探针共用核心）；`build_ma_tree` 走 env、
   `build_ma_tree_with_depth` 保持默认参数；
3. encoder 拆 `encode_ma_tree` 内核 + `encode_ma_variant_with_params`；生产 variant 0 接
   `ma_train_params()`；
4. 新探针 `--probe-ma-train-ab`：Stage 1（树头 + 条件熵代理，用生产训练函数建树）排序，
   Stage 2（真实字节 + 整帧竞争 `min(MA,G,U)`）定胜负。

**实测（Stage 2 真实字节，整帧竞争 min(MA,G,U)，负 = 更小）**：

| 组 | 帧数 | 默认锚点 base | 最优组合 | 收益 |
|---|---:|---:|---|---:|
| 2000 | 7 | 7,738,475 | g0.001·log·d6 | **−12.72%** |
| 2-12-4 | 3 | 69,856,269 | g0.001·log·d6 | **−5.18%** |
| 1000 | 13 | 13,034,026 | g0.001·log·d6 | **−4.91%** |
| 2-15-4 | 3 | 3,193,762 | g0.02·log·d4+ | **−3.16%** |
| 10-1-10 | 9 | 37,919,205 | g0.001·log·d6 | **−3.02%** |
| 30-1-36 | 5/36 采样 | 32,343,485 | g0.001·log·d6 | −2.39% |

**结论**：
1. **第二杠杆显著有效**：6 组中 5 组 ≥3% 门槛（最高 −12.72%），远优于 §69 深度杠杆
   （−0.3~−1.2%）——证实「训练参数才是瓶颈」的判断。
2. **最优组合高度一致**：`gain=0.001 · log 阈值集（20 个，1..255）· depth=6`。`log` 集
   全面优于 `dense`/`base`——**阈值密度（尤其 >30 的尾区）是主杠杆**；低 gain 允许更细分裂。
3. 30-1-36（最高熵大图，5 帧采样）−2.39% 略低于门槛但接近；全帧可能略变。

**裁决——显著正收益，建议实施**：
1. 建议将默认训练参数改为 `gain=0.001 · log 阈值集 · depth=6`（产物变小，非回归）；
2. 实施前需：① 全 `test/png` 组扫描确认无劣化组；② 因改变默认产物，需重新标定字节基线
   （bench 锚点 + README 指标）；③ 评估「新旧参数双候选竞争」以保障单调不劣化
   （当前固定参数不保证逐内容不劣化）；④ 速度影响评估（建树 16K 样本，预计极小）；
3. 探针 `--probe-ma-train-ab` 保留为回归锚点。
